Archive, search and export

Earshot keeps every session. The Archive is where you read one back, search what was said, drop markers on the timeline, and export a session for a show report.

Every role can read the Archive, search it and export from it. Adding a marker needs an operator or an admin.

The mock show "Spring Tour at Harbour Hall". Invented sessions and lines, not a real show.

Sessions​

Every time Earshot starts, it begins a new session. An admin can also start one by hand with New session… under Setup, Show file (see Show files).

The list on the left shows sessions newest first. Each has the show's name, its date and start time, and how long it ran. The session that is running now carries a Live now badge.

  1. Pick a session to read it. Until you do, the screen says "Pick a session to read it."
  2. The header shows its date, start time and length ("so far", for the live one).
  3. Lines are listed oldest first, with the time at the right of each line.

On a phone the list and the transcript take turns. A back arrow, Back to sessions, returns to the list.

Show only some channels​

Above the transcript is a row of chips: All channels, then one per channel.

  • Press a channel's chip to show only that channel. Press more chips to add channels.
  • Press All channels to clear them.
  • If nothing matches, the screen says "No lines from these channels in this session."

The chips also decide what Export saves: see below.

Long sessions​

A long session is loaded a part at a time. Load earlier lines at the top and Load later lines at the bottom page through it.

Search what was said​

Type in Search what was said at the top. Results appear as you type.

  • This session searches the session you have open. All sessions searches every session Earshot has kept.
  • Results are headed Search results with a count ("27 matches"). Each shows the channel, the time, the person's name if the line has one, and the line with your words highlighted. Across all sessions, each also says which session it is from.
  • Press a result to open the transcript at that line. Results takes you back to the list of matches, and Back to transcript closes it.
  • If nothing is found: "Nothing matches “your words” in this session." (or "in any session").

Searching the mock show for "standby". Not a real show.

How the search reads what you type:

You typeIt finds
standbyLines containing the word "standby". Capitals do not matter.
lighting cueLines containing both words, anywhere in the line, in any order.
cue 42Lines containing "cue" and "42".
standLines containing the word "stand". It does not find "standby": whole words only.
  • Punctuation and symbols are ignored. There are no special search commands.
  • It searches the text as saved, that is, after glossary corrections and number tidying. If the recogniser heard "aleesha" and the glossary changed it to "Alesha", search for Alesha.
  • A line that was translated can also be found by words in its translation.
  • The list shows the best 50 matches. If you expected more, narrow the words or search one session at a time.

Markers​

A marker is a labelled point on the timeline, like "Act two, cue 42". Markers make a long session easy to find your way around afterwards.

To add one (operators and admins, in the session that is live now):

  1. Open the live session in the Archive.
  2. Find Markers above the transcript (on a narrow screen, press it to open it), and press Add marker.
  3. Type the Marker label (up to 120 characters), for example Act one begins. Press Add.

The marker is placed at the moment you add it.

To use one: under Markers (it shows a count, "Markers (2)"), press a marker to jump to that point in the transcript. A session with none says "No markers in this session."

Markers can also be added without touching the Archive:

  • An automation can add one with its Add a marker action, for example a marker for every cue the show caller fires. See Actions.
  • A console can add one over OSC. See OSC addresses.

Export​

Export saves the session you are reading as a file. Press it and choose TXT, CSV, JSON or SRT. While it works the screen says, for example, "Preparing CSV…", then "Saved" and the file's name.

The mock show's Archive with the Export menu open. Not a real show.

  • The file is named earshot- followed by the session's id, with the format's ending, for example earshot-01KA4T7Q9D5XJ2R8M3N6P0V1WC.csv.
  • If channel chips are on, the export keeps only those channels. The button says how many: "Export (2 ch)".
  • The export is the text as saved: corrected, tidied, and filtered if the channel filters profanity.
  • Typed lines and Earshot's own notices are included, in time order with the speech.
warning

Times in TXT and CSV files are in UTC, not your local time. On screen, Earshot shows local time. A line you saw at 19:30 in London in summer is 18:30 in the file.

The four formats, using the same three lines from an invented session that began at 18:30:00 UTC:

TXT​

For reading and for pasting into a show report. One line each: the time (UTC, to the second), the channel, the text.

[18:30:07] Stage Manager: Front of house has cleared us, the house is yours.
[18:30:21] Show Caller: Lighting cue 42, go.
[18:31:02] Stage Manager: House open

CSV​

For a spreadsheet. The first row names the columns: time,channel,speaker,kind,text.

time,channel,speaker,kind,text
2026-11-16T18:30:07.412Z,Stage Manager,,speech,"Front of house has cleared us, the house is yours."
2026-11-16T18:30:21.090Z,Show Caller,,speech,"Lighting cue 42, go."
2026-11-16T18:31:02.655Z,Stage Manager,Ana,typed,House open
ColumnWhat is in it
timeWhen the line started, as a full date and time in UTC, to the millisecond.
channelThe channel's name.
speakerFor a typed line, the name of whoever typed it. For a spoken line that Earshot put a name to, the id that person has in the show, not their name. Empty otherwise.
kindspeech, typed, or system (a notice Earshot wrote itself).
textThe line. It is wrapped in quotation marks when it contains a comma, a quotation mark or a line break.

SRT​

Subtitle format, for laying the transcript against a video recording of the show. Times count from the start of the session, not from the clock.

1
00:00:07,412 --> 00:00:10,980
Stage Manager: Front of house has cleared us, the house is yours.

2
00:00:21,090 --> 00:00:22,870
Show Caller: Lighting cue 42, go.

3
00:01:02,655 --> 00:01:04,655
Stage Manager: House open

Each entry runs from when the person started to when they stopped. A line with no length, such as a typed line, is given 2 seconds. To line it up with a video, you need to know how far into the session the recording started.

JSON​

For other software. It is a list of every line with everything Earshot stored about it.

[
  {
    "id": "01KA4T8E2Y6ZB4N9Q7R1S3T5VX",
    "session_id": "01KA4T7Q9D5XJ2R8M3N6P0V1WC",
    "channel_id": "01KA2M5H8K0C3F6J9P2S5V8Y1B",
    "started_at": 1794853821090,
    "ended_at": 1794853822870,
    "text": "Lighting cue 42, go.",
    "raw_text": "Lighting Q42, go.",
    "words": [
      { "text": "Lighting", "confidence": 0.98, "t0_ms": 0, "t1_ms": 420 },
      { "text": "cue", "confidence": 0.91, "t0_ms": 480, "t1_ms": 700 }
    ],
    "language": "en",
    "speaker_id": null,
    "kind": "speech",
    "author": null,
    "keyword_hits": [],
    "has_clip": true,
    "latency_ms": 1040,
    "confidence": 0.94,
    "translations": {}
  }
]

An invented line, shortened: a real one lists every word. The ids are made up.

FieldWhat it is
id, session_id, channel_idIds of the line, its session and its channel. The channel is an id here, not a name.
started_at, ended_atWhen the person started and stopped, in milliseconds since 1 January 1970 UTC.
textThe line as saved.
raw_textWhat the recogniser heard, when that differs from text. Otherwise null. For anyone below operator it is always null.
wordsEach word with how sure Earshot was (0 to 1) and where it falls in the line, in milliseconds from the line's start.
languageThe language of the line, when known.
speaker_idThe id of the person Earshot recognised, or null.
kindspeech, typed or system.
authorWho typed it, for a typed line.
keyword_hitsWhere an automation's phrase matched in the text.
has_clipWhether saved audio exists for the line. The audio itself is not in the export.
latency_msHow long after the person stopped the final text was ready.
confidenceHow sure Earshot was of the whole line (0 to 1), when known.
translationsAny translations made of the line, by language code.

JSON is the only format that carries what was heard (raw_text). The others never do.

Exporting from a script​

The same export is available from the host's web address, for a script that files the show report every night. See The API.

A worked example: last night's show report​

The production manager wants every call the show caller and stage manager made last night, as a spreadsheet, and wants to know when the interval began.

  1. Open Archive. Pick last night's session from the list.
  2. Under Markers, press Interval. The transcript jumps there, and the marker's time is the answer.
  3. Press the Show Caller chip, then the Stage Manager chip.
  4. Press Export, which now reads "Export (2 ch)", and choose CSV.
  5. Open the file in a spreadsheet. Remember the times are UTC.

To find every time a particular cue was mentioned in the whole run, type cue 42 in Search what was said and press All sessions.

Limits​

  • There is no button for deleting past sessions in this build. How to start a fresh history by hand is in Privacy.
  • Anyone who can connect can read the Archive and export it. In Open mode that is everyone on the network. See Who can connect.
  • Anything said while the host was not running was not written down.
  • Clearing a channel's transcript removes its lines, and makes their saved audio unreachable at once. See Replay a line's audio.
