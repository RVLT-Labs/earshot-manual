Show files

Open Setup, then Show file. The screen says: "The show file holds your channels, groups, automations, destinations and glossary, so you can carry a show to another machine. It does not hold this computer's settings or the transcript."

The screen has four parts: Name, Export, Import and Session.

Who can do this

Only admins.

The mock show. Not a real show.

Name​

Show name is what appears in the header on every screen, and it becomes the name of the exported file. Type a new one and press Save name. The screen says "Show name saved."

Export​

Press Export show file. Your browser downloads a file named after the show and ending .earshot.json. The screen says "Exported. The file has no passwords or API keys in it."

In the fileNot in the file
Channels and their settingsThe password for joining
GroupsCloud keys (Deepgram, DeepL, Anthropic)
Automations (triggers, conditions, actions)Link codes of channels from other Earshot computers
OSC destinationsLearned voices
The glossaryWebhook addresses, HTTP header values and shell commands (hidden)
People's names and coloursThe path of web addresses in HTTP actions (cut back to the host name)
The addresses of linked channels, without their codesThe transcript, markers and saved audio
The file is not secret-free in every sense

It has no passwords or keys, but it does carry your channel names, crew names, glossary and the host names your automations talk to. Treat it like any other show paperwork.

Import​

Press Choose a show file… and pick a .earshot.json file. Earshot asks "Import this show file?" before it does anything:

Importing the file replaces this show's channels, groups, automations, destinations and glossary with the ones in the file. This computer's settings are kept: access, OSC and MIDI input, cloud keys, start armed and shell commands. Importing never arms the show.

Secrets are not stored in show files. Webhook addresses, HTTP header values and shell commands in the file must be entered again, and the automations that use them arrive switched off and marked “Not running”.

If the file is rejected, your current show is left as it is.

Press Import show to go ahead.

Afterwards the screen says "Imported file. This computer's settings were kept and the show is not armed. Any automation that needs a webhook address, header value or shell command is switched off and marked “Not running” until you enter it again."

The rules of an import​

  • It replaces show content. This show's channels, groups, automations, destinations and glossary are replaced by the ones in the file. It is not a merge.
  • It keeps every local setting of this computer. Access (who can connect, the password), OSC and MIDI input and their level, allowed devices, cloud keys, Start armed, the shell commands switch, the default speech model and the translation settings all stay as they are. A show file cannot change who is allowed in.
  • It never arms. If the show was Armed when you imported, it goes Safe.
  • Learned voices are never imported. People arrive with their names and colours. Voices already learned on this computer stay for people with the same id. Everything else must be learned again.
  • Secrets must be typed in again. A webhook address, an HTTP header value or an HTTP address hidden in the export arrives empty. Those automations come in switched off, marked "Not running", with a problem saying what to enter. Open each one, fill it in and switch it on.
  • Automations that run shell commands always arrive switched off, whatever this computer's shell setting is. Importing never turns on Allow automations to run shell commands. Switch each automation on yourself after you have read what it does.
  • An imported linked channel with an unusable address is kept, switched off, with its address cleared (it might have held a code). Type the address again.
  • A rejected file changes nothing. Your show is left as it was.
An import replaces the show you have

There is no undo button. Export the current show first if you might want it back.

Session​

A session is one continuous transcript. Earshot starts a new one every time it starts. The screen shows when the current one began.

Press New session… to start a fresh one by hand, for example between the matinee and the evening show. Earshot asks "Start a new session?" and says "The live transcript starts again from empty. The current session is kept in the Archive." Press Start new session.

Nothing is deleted. The old session is in the Archive, where you can read, search and export it.

Example: moving a show to the venue machine​

You built "Spring Tour at Harbour Hall" on a laptop in the office. The venue has a rack computer that will run it.

On the laptop

  1. Open Setup, Show file, and press Export show file.
  2. Copy the downloaded .earshot.json file to a USB stick, with a note of every secret the show uses: webhook addresses, HTTP header values and full web addresses of HTTP actions, shell commands, link codes, cloud keys.

On the venue computer

  1. Start Earshot and open it as an admin. Download the speech models while you have internet. See Models.
  2. Open Setup, Show file, Choose a show file…, pick the file, read the question, and press Import show.

Then put back what a show file does not carry

  1. Inputs. The channels arrive pointing at the audio device the laptop used. Open Setup, Channels (or Patch) and point each one at the venue interface's inputs. Check each level meter moves.
  2. Automations marked "Not running". Open Automations and press Show it (or Show only these). For each one, type the web address, header value or webhook address again, read it, and switch it on. See When an automation is not running.
  3. Shell automations. They arrive switched off. If you use them, turn on Setup, Show control, Allow automations to run shell commands, then read and switch on each automation.
  4. OSC destinations. They come across with the show. In the automation editor, under OSC destinations, check each one has the venue console's address, port and protocol.
  5. Voices. Every person arrives with a name, a colour and No voice yet. Learn each voice again, on the channel they will use. See People.
  6. Linked channels. Type each link code again (and the address, if it arrived cleared). See Showing another Earshot computer's channels.
  7. This computer's own settings. An import does not touch them, so they are whatever this computer had. Set them here: who can connect and the password (Access), OSC and MIDI input (Show control), cloud keys and saved-audio limits (Cloud & audio), the default speech model (Models).
  8. Test. With the show Safe, run every phrase through the Test bench, say each one on the real channel, and check Activity for "would have fired". Then go through the before-show checklist.
Do the move with time to spare

Models need internet to download, and voices need each person on comms. Neither can be done five minutes before the house opens.

Where the live show is kept​

While Earshot runs, the show lives in show.earshot.json (with a .bak copy) in the host's data folder. That file is not the same as an export: it also holds this computer's settings, cloud keys, link codes and learned voices. Do not hand it to anyone. Use Export show file for a copy that is safe to move. See Data and files.
