Building an automation

An automation is a trigger, optional conditions, and a list of actions. This page builds one from start to finish: the "Go cue" automation from the mock show. When the show caller says "go cue forty two", it sends an OSC message with the number 42 to a lighting desk and drops a marker in the Archive.

Who can do this

Only admins can build and edit automations. Operators see the list, can press Run now and can use the Test bench. Viewers see the list only ("This list is read-only for viewers."). See roles.

Read Safe and Armed first. Everything you build here only logs "would have fired" until the show is Armed.

The Automations screen​

Open Automations. On a phone it is under More.

The Automations list. Mock show, not a real show.

At the top are two tabs, Automations and Test bench, and a line that says whether the show is Safe or ARMED. Each automation in the list shows:

On the rowWhat it is
The name, and a Problem badge if something is wrongSee When an automation is not running.
The Enabled switch, with "On" or "Off" beside itA disabled automation never fires, but keeps its settings. Non-admins see an "Enabled" or "Disabled" badge instead.
A summary of the triggerFor example Hears "go cue {number}" on Show Caller.
"2 actions"Press it to list what the automation does. An automation that fires on draft text also says "fires on draft text".
When it last fired"Not fired since you connected", or "Last fired 12:50:04 (dry run: nothing was sent)" or "(sent)".
Run nowRuns it by hand. See Run now. Operators and admins.
Edit, Duplicate, DeleteAdmins only. A duplicate is made switched off, so it cannot double-fire, and opens in the editor. Delete asks first: "It will stop working straight away and cannot be brought back. Other automations that run it will show a problem."

A duplicate does not copy secrets. A web-request trigger gets a fresh address of its own, and HTTP header values are left empty for you to enter again.

Step 1: New automation​

Press New automation. The editor opens. It has five parts, in order: Basics, When, Only if, Then and Safety.

The editor, open on "Go cue". Mock show, not a real show.

Step 2: Basics​

Basics. Mock show, not a real show.

FieldWhat to enterNotes
NameGo cueWhat people see in the list and in Activity. Two automations may share a name, but the editor warns that they will be hard to tell apart.
Short namego-cue (filled in for you)Used in web addresses and OSC. Lower-case a to z, digits and single hyphens. On a new automation it is a preview: "The engine chooses the final short name, or type your own".
EnabledOn"A disabled automation never fires, but keeps its settings."

Step 3: When (the trigger)​

When. Mock show, not a real show.

  1. Under This automation starts when it, leave A spoken phrase.
  2. Under Match mode, leave Exact phrase.
  3. In Phrase 1, type go cue {number}.
  4. Under Where to listen, Channels, tick Show Caller.

The braces make a capture. {number} stands for exactly one spoken word. When someone says "go cue forty two", Earshot has already turned "forty two" into 42, so the capture is 42. The editor confirms it under the phrase: "Captures you can use in actions: {{capture.number}}".

The editor also reminds you: "Automations hear what was said. Glossary corrections change only what you read."

Leaving a Where to listen list empty means "listen to everything". Ticking Show Caller means this automation ignores the same words on every other channel.

Every trigger and every field is described in Triggers and conditions. How numbers are heard, and what Earshot refuses, is in How Earshot hears numbers.

Step 4: Only if (conditions)​

Only if. Mock show, not a real show.

Leave this empty for now. It reads "No extra conditions: it runs whenever the trigger fires."

Conditions are optional extra checks, and all of them must be true. To add one, choose its kind in the box and press Add condition. The kinds are listed in Triggers and conditions.

Step 5: Then (the actions)​

Actions run in order, top to bottom.

Then, on a different automation ("Roll video") so you can see three kinds of action. Mock show, not a real show.

Add the OSC destination​

A Send OSC action goes to a destination: a lighting desk, a video server, a QLab machine. Make the destination once and every automation can use it.

  1. In the box at the bottom of Then, choose Send OSC and press Add action.
  2. Press Manage destinations, then Add a destination.
  3. Enter Name Eos, Host 10.0.1.20, Port 8000, Protocol UDP. Use your own desk's address and port.
  4. Press Add destination, then Done.

OSC destinations. The addresses are made up. Mock show, not a real show.

Fill in the Send OSC action​

FieldWhat to enter
DestinationEos (UDP 10.0.1.20:8000)
Address/eos/cue/{{capture.number}}/fire
ArgumentsNone. It reads "No arguments: a bare message."

{{capture.number}} is a variable. When the automation fires, Earshot puts the captured number in its place, so the desk receives /eos/cue/42/fire. You can type a variable or pick it from Insert variable… under the field. See Variables.

Check the address against your desk

/eos/cue/…/fire is the receiving product's own OSC address, not Earshot's. Check the exact address in that product's documentation. Earshot has only been tried against stand-ins on one Mac, never against a real console. See Limits and known behaviour.

Add the marker​

  1. Choose Add a marker in the box at the bottom and press Add action.
  2. In Marker text, type Cue {{capture.number}}.

The marker "appears on the timeline in the Archive", so afterwards you can jump to the moment each cue was called. See Archive and markers.

Use the arrows on an action to move it up or down, and the bin to remove it. Every action is described in Actions.

Step 6: Safety​

Safety. Mock show, not a real show.

FieldLeave it atWhy
Cooldown (milliseconds)2000"After it fires, it ignores the trigger for this long. 0 means no cooldown. It always fires at most once per utterance." Two seconds stops a repeated call from sending the cue twice.
Fire onFinal text (recommended)It waits for the finished line. Draft text (faster, less safe) can fire while the person is still speaking.

Step 7: Save​

Press Save automation. If something is wrong, the editor lists it ("1 thing to fix before saving:") and does not save. Yellow "Check:" notes are warnings: they do not stop you saving.

If you try to leave with unsaved changes, Earshot asks "Discard your changes?" with Keep editing and Discard changes.

Step 8: Try it on the Test bench​

  1. Open the Test bench tab.
  2. Under Phrase to test, type go cue forty two, the way it would be said.
  3. Under Channel, choose Show Caller.
  4. Press Test phrase.

The Test bench after testing "go cue forty two". Mock show, not a real show.

The result shows "1 automation would fire.", then a card for Go cue with a Would have fired badge and one line per action, each marked "Would run". The OSC line shows the address with 42 in place of the variable.

Nothing is ever sent from the Test bench, whether the show is Safe or Armed. See Testing.

Now try the phrases that should not fire. go cue 7 and 8 matches the words but is refused for its number, and the bench does not say why. That reason only appears in Activity when a real line is spoken. See How Earshot hears numbers.

Step 9: Say it while Safe​

With the header showing Safe, have the show caller say "go cue forty two" on the real channel.

  1. Read the line in the Feed. Check that it was heard the way you expect.
  2. Open Activity. Look for a row like Would have fired Go cue: phrase "…" on Show Caller, where the dots are the words that matched, with a Dry run badge.

The Activity log. Mock show, not a real show.

If there is no such row, or the row says "Go cue" did not fire: …, the reason is on the row. See A cue did not fire.

Step 10: Arm, and say it again​

Only when the dry runs look right:

  1. Hold Hold to arm for about 0.7 seconds. The header turns red.
  2. Wait a beat. A line fires only if the show was Armed from the moment the words began.
  3. Have the caller say the line again.
  4. Check Activity for Fired Go cue: … and check the desk.
  5. Press Make safe when you are done.
Armed really sends

While the show is Armed, every enabled automation can fire, not only the one you are testing. Check the list before you arm.
