Variables in actions

A variable is a name in double braces, such as {{capture.number}}. When an automation fires, Earshot replaces it with a value from whatever set the automation off: the number that was said, the channel it was said on, an argument from an OSC message.

This is how one automation, go cue {number}, can fire any cue number instead of needing one automation per cue.

The short version​

You writeWhereIt becomes
go cue {number}In the trigger's phrase (single braces)A capture called number.
/eos/cue/{{capture.number}}/fireIn an action (double braces)/eos/cue/42/fire when someone says "go cue forty two".

Single braces catch a value in a trigger. Double braces use a value in an action.

In the editor, every field that accepts variables has an Insert variable… box under it. It lists exactly the variables your trigger provides, with a description of each, and puts the one you choose at the cursor.

Which variables each trigger provides​

A spoken phrase​

VariableWhat it holds
{{text}}The whole line that was heard.
{{match}}The part of the line that matched.
{{capture.NAME}}The word heard where {NAME} is in the phrase. With Regular expression, the named group NAME.
{{capture.1}}, {{capture.2}} …The same captures by position, counting from 1.
{{channel.name}}Name of the channel it came from.
{{channel.slug}}Short, OSC-safe name of that channel.
{{speaker.name}}Who was speaking, if known.

Three things to know:

  • {{text}} and {{match}} are the words as Earshot heard them: numbers and show words tidied ("forty two" is 42, "stand by" is "standby"), but glossary corrections not applied. Automations never see the corrected text.
  • A capture holds one word. A whole spoken number counts as one word, so {number} on "cue twelve point five" is 12.5.
  • {{speaker.name}} is filled in only when Earshot already knows who spoke at the moment the automation fires. A name normally arrives a moment after the line, and an automation that is not limited to people does not wait for it. Expect it to be empty most of the time.

An incoming OSC message​

VariableWhat it holds
{{osc.address}}The address that arrived.
{{osc.args.0}}First argument (count from 0).
{{osc.args.1}}Second argument, and so on.
{{capture.NAME}}The part of the address where {NAME} is in the pattern.
{{capture.1}}, {{capture.2}} …The same captures by position, counting from 1.

An incoming MIDI message​

VariableWhat it holdsFilled in for
{{midi.port}}Input port the message arrived on.Every message
{{midi.channel}}MIDI channel, 1 to 16.Every message
{{midi.note}}Note number.Note on, Note off
{{midi.velocity}}Velocity.Note on, Note off
{{midi.controller}}Controller number.Control change
{{midi.value}}Controller value.Control change
{{midi.program}}Program number.Program change

A web request​

VariableWhat it holds
{{var.body}}The request body, as text. Empty if the request had none.

Manual only​

VariableWhat it holds
{{var.NAME}}A value the caller supplied. Replace NAME with the name the caller used.

Callers that can supply values:

  • The HTTP API. A request that runs the automation can carry values. See The HTTP API.
  • Run another automation. The first automation's values are handed on with var. in front of each name: its {{capture.number}} is {{var.capture.number}} in the second automation, and its {{text}} is {{var.text}}.

Run now on the list supplies no values, so every {{var.NAME}} is empty.

A channel's health​

VariableWhat it holds
{{channel.name}}Name of the channel the event is about.
{{channel.slug}}Short, OSC-safe name of that channel.

Which fields accept variables​

ActionFields that accept variables
Send OSCAddress, and each argument's value
Send MIDINote, Velocity, Controller, Value, Program
HTTP requestURL and Body (not header names or values)
Flash an alertAlert text
Send text to a channelChannel name, short name or number, and Text
Add a markerMarker text
Control the screenChannel (for Select a channel and Mark as read)
Run a shell commandNone. See below.

Flag names, header values and the other fields are used exactly as you typed them.

Writing a variable​

  • Write {{name}} or {{ name }}. Spaces inside the braces do not matter.
  • A name is made of letters, digits, _, . and -.
  • A variable your trigger does not provide is replaced with nothing. The editor warns you: "{{capture.cue}} is not filled in by this trigger, so it will be empty."
  • To write two real opening braces, put a backslash first: \{{ comes out as {{.
  • A {{ with no closing }} is sent as plain text. The editor warns: "A {{ has no closing }}, so it will be sent as plain text."
  • There is no nesting, no arithmetic and no formatting. A variable is replaced by its value and nothing else. You cannot add 1 to a cue number or pad it with zeros.

The safety rules​

A variable carries something that was said, or something that arrived from the network. Earshot limits what such a value can do.

In an OSC address​

A value put into an OSC address may not be empty and may not contain any of:

/ * ? [ ] { } , #   or a space

If it does, the action is skipped and the reason is logged. The value is never cleaned up and sent anyway. A mis-heard word can therefore never turn /eos/cue/{{capture.number}}/fire into /eos/cue/*/fire.

This applies only to values that come from variables. The parts of the address you typed yourself can contain anything.

OSC arguments are not addresses, so a text argument may contain anything. A number argument must still read as a number of its type, or the action is skipped.

In a web address​

A value put into a URL is percent-encoded: everything except letters, digits and - . _ ~ is written as % and a code. So a ?, &, / or # in something that was said cannot change which address is called.

A value put into a request Body is not encoded. It goes in as it is.

In a shell command​

A shell command is not a template. A command containing {{ is refused. Values are passed as environment variables instead, named EARSHOT_ followed by the variable's name in capitals with every other character turned into _:

VariableIn a shell command
{{text}}"$EARSHOT_TEXT"
{{capture.number}}"$EARSHOT_CAPTURE_NUMBER"
{{channel.slug}}"$EARSHOT_CHANNEL_SLUG"
{{osc.args.0}}"$EARSHOT_OSC_ARGS_0"

This way spoken text can never become part of the command itself. See Run a shell command.

Worked examples​

A cue number into an OSC address​

Phrasego cue {number}
ActionSend OSC, address /eos/cue/{{capture.number}}/fire
Said{{capture.number}}Sent
"Go cue forty two."42/eos/cue/42/fire
"Go Q 7."7/eos/cue/7/fire
"Go cue twelve point five."12.5/eos/cue/12.5/fire
"Go cue 7 and 8."(refused)Nothing. Activity: "Go cue" did not fire: the number may be incomplete: …

Whether your desk accepts 12.5 in an address is for the desk's documentation to say.

A cue number as an OSC argument​

Phrasesound cue {n} go
ActionSend OSC, address /sound/go, one argument: Whole number, value {{capture.n}}
SaidSent
"Sound cue nine, go."/sound/go with the whole number 9
"Sound cue nine point five, go."Nothing from this action. 9.5 is not a whole number, so the action is skipped and Activity says why.

Two captures​

Phrasefade {a} to {b}
ActionSend OSC, address /fader/{{capture.a}}, one argument: Whole number, value {{capture.b}}

"Fade three to five" sends /fader/3 with the whole number 5. Always put a word between two captures. fade {a} {b} is rejected. See How Earshot hears numbers.

The channel into an alert​

Phrase (Any of)blackout, kill the lights
ActionFlash an alert, text BLACKOUT called by {{channel.name}}

"Kill the lights" on Deck Left shows "BLACKOUT called by Deck Left".

An OSC argument passed on​

TriggerAn incoming OSC message, pattern /desk/page/{page}/go
ActionAdd a marker, text Page {{capture.page}}, level {{osc.args.0}}

A console sending /desk/page/3/go with the argument 0.8 adds the marker "Page 3, level 0.8".

Something said, into a web address​

Phrase (Regular expression)video (?P<n>\d+) go
ActionHTTP request, POST, URL http://10.0.1.40:8080/play/{{capture.n}}

"Video four go" calls http://10.0.1.40:8080/play/4.

A request body into a channel​

TriggerA web request
ActionSend text to a channel, a fixed channel, text From the web: {{var.body}}

Calling the automation's address with the body house open writes "From the web: house open" into that channel as a typed line.
