Testing: Run now, the Test bench and Activity

Earshot gives you three ways to find out what an automation will do before it matters:

ToolWhat it answersDoes it send?
Test bench"If someone said this, which automations would fire, and what would each action do?"Never. Always a dry run.
Run now"What does this automation do when it runs?"Only while the show is Armed, and it asks first.
Activity"What actually happened, and why did that cue not fire?"It is a log. It sends nothing.

The Test bench​

Open Automations, then the Test bench tab.

Who can use it

Operators and admins. A viewer sees "The test bench needs operator access".

The Test bench. Mock show, not a real show.

The notice at the top says: "Nothing is ever sent from here. The test bench always runs as a dry run, whether the show is Safe or Armed. It shows what would fire and what each action would do."

  1. Under Phrase to test, type the phrase. "Type it the way it would be said, for example “go cue forty two”." It is cleaned up the same way spoken text is.
  2. Under Channel, choose the channel it would be heard on, or leave Any channel. "Automations can be limited to certain channels, so pick the one it would be heard on."
  3. Press Test phrase.

Use last heard line copies the latest spoken line into the box (from the chosen channel, if you chose one). Use it right after someone has said the call for real, to see what Earshot makes of exactly what it heard.

Reading the result​

  • "1 automation would fire." (or more), then one card per automation.
  • Each card has the automation's name, a Would have fired badge, what set it off, and one line per action marked Would run, with its variables filled in. An action that could not run is marked Skipped, with the reason.
  • If nothing matches: "No automation would fire. Check that it is enabled, that the words and channel match, that its conditions hold, and that it is not still cooling down."

Under the result, Recent tests lists what you have tried, each marked "1 matched" or "no match". Press one to see it again.

What the Test bench does not tell you​

  • With "Any channel", an automation limited to channels or groups does not match. Pick the channel the line would be heard on.
  • It ignores Cooldown and Fire on. The text is treated as a finished line, and an automation that is cooling down still shows as firing.
  • It does not say why something was refused. A phrase that matches the words but is refused for its number ("go cue 7 and 8") simply shows no automation. For the reason, watch Activity when the real line is spoken.
  • It cannot test a voice. An automation limited to people needs a real voice, and the bench has none.
  • It tests what you typed, not what the recogniser will hear. If the recogniser mis-hears the caller, the bench cannot know. That is what the rehearsal below is for.

Run now​

On the Automations list, every automation has a Run now button (operators and admins). It runs that one automation by hand, skipping its trigger.

The show isThe button readsWhat happens
SafeRun now (dry run)It runs as a dry run and says so: "Dry run — nothing was sent".
ArmedRun now (live), in redIt asks first. See below.

Run now on the mock show's Go cue while Safe. With no spoken number to fill in, its OSC action is skipped and says why. Not a real show.

Run now while the show is Armed. Mock show, not a real show.

While Armed, pressing it shows "Armed: this really sends." with Cancel and Send live. Nothing goes until you press Send live. The result is headed "Fired".

After a run, a card under the automation shows what each action did ("Ran") or would have done ("Would run"). If nothing ran it says "Nothing matched — nothing was sent" and "It may be disabled or cooling down, or its conditions did not hold."

Things to know:

  • Run now still respects the automation's conditions and cooldown. A flag or time-of-day condition that is not met stops it.
  • If you press it twice less than 0.1 seconds apart, the second press is refused.
  • Run now supplies no values. Any {{capture.…}} in the actions is empty, so an OSC address built from one is skipped. To test with a number, use the Test bench.
  • You cannot Run now an automation limited to people: no voice was heard.
  • If an automation is not running (it has a Problem), the button says "Run now will do nothing: the host is not running this automation. The reason is listed under it."
A known edge

Run now is tied to Armed or Safe at the moment the engine receives it, normally under a thousandth of a second after you press. A Run now pressed as a test in Safe at the very instant someone else arms could really send. See Safe and Armed.

The Activity log​

Open Activity (on a phone, under More). Every role can read it. It lists, newest at the bottom, every OSC, MIDI and web message in and out, and every decision an automation made.

The Activity log. Mock show, not a real show.

When it is empty it says "Nothing yet. OSC, MIDI and HTTP messages and automation decisions appear here as they happen."

A row​

PartWhat it shows
TimeTo the millisecond.
KindOSC, MIDI, HTTP, Automation, Connection or System.
DirectionIn, Out or Internal.
SummaryWhat happened, in plain words.
Dry runNothing was sent: the show was Safe, or it was the Test bench.
FailedSomething did not work. Press the arrow at the end of the row to read why.

If you scroll up to read back, Back to live returns to the newest row.

What the rows say​

RowWhat it means
Fired Go cue: phrase "…" on Show CallerIt really fired. The show was Armed.
Would have fired Go cue: phrase "…" on Show Caller with Dry runIt matched, and Safe held it back. This is the row you want to see in rehearsal.
Fired Standby chime: manualRun now, the API or OSC ran it by name.
"Go cue" did not fire: heard before the show was armedThe words began while the show was Safe.
"Go cue" did not fire: Safe was pressed after this was saidSafe was pressed before the cue went out.
"Go cue" did not fire: the start of this line was missedEarshot was restarting that channel when the line began.
"Go cue" did not fire: cooling down (1400 ms left)It fired less than its Cooldown ago.
"Go cue" did not fire: condition not met: flag show-mode is not setAn Only if condition was false. The row names it.
"Go cue" did not fire: the number may be incomplete: …Refused for its number. See How Earshot hears numbers.
"Go cue" did not fire: voice not recognisedA people-limited automation was not sure who spoke.
"Go cue" did not fire: no voice was heard for this triggerA people-limited automation was started by something with no voice.
"Go cue" did not fire: the automation is disabled or invalidSomething tried to run it by name, and it is switched off or has a problem.
"Go cue" did not fire: loop guard: the chain's limit was reached (each automation once per chain, at most 32 firings, 8 hops)A chain of automations hit its limit.

Inside the brackets is what set it off: phrase "…" on <channel>, OSC <address>, MIDI … on <port>, webhook, manual, chained (hop 1), or a health event such as device lost.

A fired row marked Failed means at least one action did not go. Open the row. Typical reasons are "not sent: the show was made Safe", "not sent: the MIDI port was busy for more than 1 s", or an OSC address value that was not safe to send. The full list is in Actions.

Refused OSC from a console is logged here too, at most once per sender every 10 seconds, with a count. See OSC input.

Viewers and operators see web-request addresses cut back to the host, and never see a web-request trigger's secret path.

A rehearsal routine​

Do this for every phrase automation before the first show. It takes a few minutes per cue.

  1. Bench. Type the phrase as it will be said, pick the channel, press Test phrase. Check the automation fires and each action has the right address and number.
  2. Bench, the other way. Type things that must not fire: the standby call, a different cue word, a list of cues. Check that no automation would fire.
  3. Say it in Safe. With the header showing Safe, have the real caller say it on the real channel, at show level, with the room as loud as it will be.
  4. Read the Feed. Was it heard the way you expected? If a word keeps coming out wrong, add the mis-hearing to the automation's phrases.
  5. Read Activity. Look for Would have fired … with Dry run. If there is a did not fire: row instead, the reason is on it.
  6. Say it three more times. One good result is not enough. Also say the standby and the near misses, and check they stay quiet.
  7. Check the cooldown. Say the cue twice, a second apart. The second should say cooling down.
  8. Arm. Hold Hold to arm. Wait a beat. Say it once. Check Activity for Fired … and check the device received it.
  9. Make safe.
What rehearsal cannot prove

Accuracy in a loud venue is unverified, and Earshot has never been run against a real console. Your rehearsal on your own comms and your own desk is the only evidence there is for your show. See Limits and known behaviour.

Then go through the before-show checklist.
