Triggers and conditions

This page is the reference for two parts of the automation editor: When (the trigger, "What sets it off.") and Only if (the conditions, "Extra checks. All of them must be true.").

For a guided first build, see Building an automation. Whatever the trigger, nothing is sent unless the show is Armed.

The six triggers​

Under This automation starts when it, choose one:

TriggerThe editor saysFires when
A spoken phrase"Fires when someone says it on a channel."Someone says it on a channel Earshot is listening to.
An incoming OSC message"Fires when a console or controller sends a matching address."A device sends a matching OSC address to Earshot.
An incoming MIDI message"Fires on a note, controller or program change."A matching message arrives on a MIDI input you ticked in Setup.
A web request"Fires when something calls this automation's URL."Something calls the automation's secret web address.
Manual only"Fires from the Run now button, the API, or another automation."Nothing starts it on its own.
A channel's health"Fires when a channel's device drops, recovers, or goes quiet."A channel's device is lost, recovers, or has been silent for a set time.

Changing the trigger kind replaces the trigger's settings with that kind's defaults.

A spoken phrase​

A spoken-phrase trigger. Mock show, not a real show.

The editor says at the top: "Automations hear what was said. Glossary corrections change only what you read." So do not rely on a glossary correction to make a phrase match. If a cue depends on a word the recogniser gets wrong, add the mis-hearing as another phrase.

Only real speech fires a phrase automation. Typed lines, translated text and lines from another Earshot computer never do. See How Earshot hears numbers for the full rule.

Match mode​

Match modeThe editor saysNotes
Exact phrase"The words in this order, as whole words. Use {name} to catch one word, like go cue {number}."The default. You can list several phrases, and any one will do.
Any of"Fires when any one of these words or phrases is heard."The list is headed "Words or phrases (any one will do)". Each entry follows the same rules as an exact phrase.
All of"Fires when every one of these is heard, in any order."The list is headed "Words or phrases (all must be heard)". All of them must be in the same line.
Regular expression"Advanced. One pattern, matched against the cleaned-up text (lower case, no punctuation, numbers as digits)."One Pattern field. See below.
Fuzzy"Like exact, but forgives small mis-hearings. Only words of 5 or more letters can differ, by at most 2 letters."Adds a Fuzzy distance (letters) field. See below.

In every mode Earshot matches whole words, ignoring case and punctuation. The phrase go does not match "going".

Before matching, Earshot tidies the line: spoken numbers become digits ("forty two" becomes 42), "Q42" becomes "cue 42", and "stand by" becomes "standby". So a phrase written cue 1 matches "cue one". The full list is in How Earshot hears numbers.

Phrases and captures​

Type each phrase in a Phrase box. Add a phrase adds another.

Put a name in braces to catch one spoken word: go cue {number}. The editor says: "{name} catches exactly one word (go cue {number} hears “go cue 42”) and becomes {{capture.name}}."

  • A capture catches exactly one word. say {word} on "say hello there" catches only "hello". A whole spoken number counts as one word, so cue {number} on "cue forty two" catches 42.
  • A capture name is letters, digits or _, and must be its own word. go{n} is rejected: "{n} must be its own word: put spaces around it."
  • Each capture needs its own name. A name used twice is rejected.
  • A phrase needs at least one real word. A phrase that is only a capture is rejected: "This phrase has no words to listen for, so it would match anything."
  • Earshot refuses a capture if the word it caught is part of a number it is not sure about. See How Earshot hears numbers.

Under the phrases the editor lists what you can use in actions, for example "Captures you can use in actions: {{capture.number}}". See Variables.

Regular expression​

For people who already know regular expressions. One Pattern, for example:

go cue (?P<number>\d+)

The editor says: "Matched against lower-case text with no punctuation, and spoken numbers already turned into digits (so use \d+, not “forty two”). Named groups become {{capture.name}}."

  • The match must start and end on whole words.
  • Only the first pattern is used: "Regex mode uses only the first pattern; the others are ignored."
  • If you write a number word in the pattern, the editor warns that it "will never be heard", because numbers arrive as digits.
  • The engine checks the pattern when you save.

Fuzzy​

Fuzzy matches like Exact phrase, but forgives small mis-hearings in longer words. Fuzzy distance (letters) is "How many letters may differ, 0 to 2. Only words of 5 or more letters are forgiving."

The guards that keep short cue words safe:

  • Both the word you wrote and the word heard must have at least 5 letters. Shorter words must match exactly, so "go" never matches "no".
  • Words of 5 to 7 letters may differ by 1 letter. Words of 8 or more may differ by at most 2.
  • The first letter must match.
  • A word containing a digit never fuzzy-matches.

A distance of 0 makes Fuzzy the same as Exact, and the editor says so.

Where to listen​

"Leave a list empty to listen to everything."

ListWhat ticking does
ChannelsOnly lines from these channels.
GroupsOnly lines from channels in these groups.
PeopleOnly lines Earshot is very sure were spoken by these people. Experimental.

How the lists combine, as the engine applies them:

  • A line is in range if its channel is ticked under Channels, or its channel belongs to a group ticked under Groups. Ticking a channel and a group widens the range; it does not narrow it.
  • People is a further limit on top of that.

The People list carries this warning in the editor: "Experimental. Fires only when Earshot is very sure who spoke. On a noisy comms line that is rare, and someone who sounds very like them can set it off. Do not use this for a cue that must go, or for one that must not go for the wrong person." Read Automations limited to people before you tick anyone.

Example​

FieldValue
Match modeAny of
Words or phrasesblackout, kill the lights
GroupsStage

The list shows it as Hears any of "blackout", "kill the lights" in Stage. A line "Kill the lights, please" on Deck Left (a Stage channel) matches. The same words on FOH Audio do not.

An incoming OSC message​

One field, OSC address pattern. A new trigger starts as /cue/{number}.

The editor says: "Starts with /. * matches any run of characters, ? one character, [a-c] one of a set, {go,stop} either word. A part that is only {name} catches that whole part of the address, and you can use it as {{capture.name}} in actions. Example: /cue/{number}/go hears /cue/42/go."

  • The pattern and the incoming address must have the same number of parts between slashes. * never matches across a /.
  • [!a-c] matches one character that is not in the set.
  • A part that is exactly {name} is a capture. {go} is a capture called "go"; {go,stop} is a choice between two words.
  • // is not supported.
  • Each capture name can be used only once.

OSC input must allow it. OSC input is off by default. For an OSC message to fire an automation, Controllers may send OSC to Earshot must be on, the level must be Trigger automations or Full control, and the sending device must be this computer or in the allowed list. See OSC input.

Addresses under /earshot/ are Earshot's own controls. Any other address fires the automations whose pattern matches it, so write your patterns outside /earshot/. See the OSC address reference.

Variables for actions: {{osc.address}}, {{osc.args.0}}, {{osc.args.1}} and so on, plus your captures.

Example​

FieldValue
OSC address pattern/desk/page/{page}/go

A console sending /desk/page/3/go fires it, and {{capture.page}} is 3. The list shows it as Receives OSC /desk/page/{page}/go.

The port must also be ticked under Setup, Show control, MIDI input ports, or Earshot is not listening to it. See MIDI.

The editor lists the variables: "Variables for actions: {{midi.note}}, {{midi.velocity}}, {{midi.controller}}, {{midi.value}}, {{midi.program}}, {{midi.channel}}." There is also {{midi.port}}.

MIDI triggers are exempt from the runaway stop. An automation whose MIDI output comes back in as its own trigger is limited only to about ten firings a second, until you make the show Safe.

Not tried on real gear

MIDI has been tried only in automated tests against stand-ins on one Mac. See Limits and known behaviour.

A web request​

The automation gets its own web address. Whatever calls that address fires the automation.

The path is a password

Whoever has the address can fire the automation, in any access mode, without signing in. It still obeys Armed and Safe: in Safe it is a dry run. Treat the address like a password, and do not put it in a show document everyone can read.

A new web-request trigger in the mock show. The address shown is the mock's own; a real host shows its own address. Not a real show.

  1. Press Generate new path. Earshot makes a long random path. (You can type your own in Path, but a guessable path is a weak password. It cannot contain spaces, ? or #.)
  2. The editor shows the full address under "Call this URL (shown now only: after saving, the app cannot show it again)". Press Copy URL and keep it somewhere safe.
  3. Save the automation.

The address has this shape:

http://192.168.1.20:4780/api/v1/webhooks/k3v9q2m7x1c8b5n4z6a0w2e7

From another computer, use the host's address from Setup, Access, Address for the crew in place of the one shown.

Send a POST request to it. The body, if there is one, arrives as {{var.body}}:

curl -X POST http://192.168.1.20:4780/api/v1/webhooks/k3v9q2m7x1c8b5n4z6a0w2e7 -d "house open"

After saving, nobody can read the path back, not even an admin. The editor shows "Hidden. Rotate to get a new URL. The path is a secret, so this app is never given it." To change it, press Generate new path, copy the new address, and save. The old address stops working. See saved secrets.

Things to know:

  • Calls are limited to a burst of 20, then 10 a second, from one sender to one path. More than that is answered "too many attempts".
  • A call to a path that does not exist counts as a wrong guess. Five wrong guesses lock that sender out for 30 seconds, doubling up to 15 minutes.
  • An automation started by a web request is subject to the runaway stop: more than 20 real firings in 10 seconds and it is stopped.
  • In an exported show file the path is hidden. After an import the automation arrives switched off until you give it a new path.

More on calling Earshot from scripts is in The HTTP API.

Manual only​

Nothing to fill in. The editor says: "Nothing starts this on its own. Press Run now on the list, call it from the HTTP API or an OSC command, or run it from another automation. Whoever calls it can pass values, which arrive as {{var.name}}."

Use it for:

  • a button you press yourself (Run now),
  • a set of actions several other automations share (Run another automation, see Actions),
  • something a console starts by name with /earshot/automation/<automation>/trigger (see the OSC address reference),
  • something a script starts through the API, passing values (see The HTTP API).

The list shows it as "Run by hand, the API, or another automation".

Any automation, whatever its trigger, can also be run these ways. "Manual only" just means it has no other trigger.

A channel's health​

FieldChoices
ChannelAny channel, or one channel
When itDevice lost, Recovered, Silent for a while
Seconds of silenceOnly for "Silent for a while". At least 1. A new trigger starts at 30.
  • Device lost fires when a channel's device is lost. Recovered fires when it comes back.
  • Silent for a while fires when the channel has been silent for at least that many seconds.
  • Variables for actions: {{channel.name}} and {{channel.slug}}.

It does not work on channels from another Earshot computer. A linked channel has no audio here, so it is never watched for silence or device health. A trigger set to "Any channel" ignores linked channels. One aimed only at a linked channel never fires, and is reported as a problem: "Silence triggers do not work on channels from another host."

Not tried on real hardware

Unplugging a USB interface mid-show is untested. See Limits and known behaviour.

Example​

FieldValue
ChannelAny channel
When itDevice lost

The list shows it as "Any channel loses its device". Pair it with a Flash an alert action reading Audio lost on {{channel.name}}. The whole automation is in Recipes.

Only if: conditions​

Only if, with no conditions yet. Mock show, not a real show.

Conditions are optional. With none, the editor says "No extra conditions: it runs whenever the trigger fires." With several, all of them must be true.

To add one, choose its kind in the box and press Add condition.

ConditionWhat you setWorks with
Channel is one ofTick channels.Spoken-phrase and channel-health triggers.
Channel is in a groupTick groups.Spoken-phrase and channel-health triggers.
Person is one ofTick people. Experimental, with the same warning as the People list above.Spoken-phrase triggers only.
Time of dayFrom (local time) and Until (local time). A new one starts at 19:00 to 23:00. "An end earlier than the start wraps past midnight."Every trigger.
A flag is setFlag name.Every trigger.
A flag is not setFlag name.Every trigger.
  • A condition that cannot apply to the chosen trigger shows an Ignored for this trigger badge, with "People conditions only apply to spoken-phrase triggers." or "Channel and group conditions only apply to spoken-phrase and channel-health triggers."
  • A channel, group or person condition with nothing ticked does nothing, and the editor says so.
  • The time is the host computer's local time.

Flags​

A flag is a named on/off marker that only automations use. "Flags are set and cleared by “Set a flag” actions." One automation sets the flag; another has a condition that checks it. That makes an interlock: "only fire this after the stage manager has said 'show mode'". The whole pattern is in Recipes.

Two things to know:

  • Flags are kept in the engine's memory while Earshot runs. Every flag starts cleared when Earshot starts.
  • A flag is only really set while the show is Armed. In Safe, "Set a flag" is a dry run like every other action, so the flag does not change.

When a condition stops a cue​

Activity says so, for example:

"Go cue" did not fire: condition not met: outside time window 19:00–23:00
"House lights" did not fire: condition not met: flag show-mode is not set

A people condition never passes when no voice was heard. Run now, a chained automation, OSC, MIDI, a web request and a channel-health event have no voice, so Activity says "no voice was heard for this trigger".

Where to listen, or a condition?​

For a spoken phrase, Where to listen and a channel, group or person condition do similar jobs. Use Where to listen for the plain case. The difference:

  • In Where to listen, a ticked channel and a ticked group widen the range (either will do).
  • Conditions must all be true. A "Channel is one of" condition and a "Channel is in a group" condition together narrow the range to channels that satisfy both.

Safety settings that affect triggers​

Two settings at the bottom of the editor change how a trigger behaves. They are described in Actions:

  • Cooldown (milliseconds): after an automation fires, it ignores its trigger for this long. Activity says cooling down (N ms left).
  • Fire on: Final text (recommended) or Draft text (faster, less safe). Only spoken phrases use it.
