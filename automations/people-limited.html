Automations limited to people

You can limit a phrase automation so that it fires only when a named person says the words. This is experimental. Read this whole page before you use it.

The editor's own warning

"Experimental. Fires only when Earshot is very sure who spoke. On a noisy comms line that is rare, and someone who sounds very like them can set it off. Do not use this for a cue that must go, or for one that must not go for the wrong person."

How to limit an automation​

There are two places, and they do the same job:

  • In When, under Where to listen, tick names in People.
  • Or in Only if, add a condition of the kind Person is one of and tick names.

Both need voice recognition to be working first:

  1. The voice model, Voice recognition (CAM++), is installed (Setup, Models).
  2. Each person has a learned voice (Setup, People).
  3. Separate and recognise voices on this channel is on for the channels the automation listens to (Setup, Channels).

See People: recognise voices on a shared channel.

The editor warns when it can never fire​

WarningWhat to do
"The voice model is not installed, so this cannot fire. Install it in Setup → Models."Install the voice model.
"Priya has no learned voice yet, so this cannot fire for Priya. Learn it in Setup → People."Learn that person's voice.
"Voice recognition is off on Show Caller, so this cannot fire. Turn on “Separate and recognise voices on this channel” in Setup → Channels."Switch it on for that channel.

(The names are examples. The editor names your own people and channels.)

It can fire for the wrong person​

In testing with 21 synthetic voices the strict rule named no voice that had not been learned, except within one group of three near-identical voices from the same speech engine. Inside that group it named the wrong one (the closest pair scored 0.92 against a rule that needs 0.90).

So:

  • Two people who sound very alike can set off each other's automations.
  • Someone whose voice was never learned can set one off if they sound almost the same as a learned person.
  • No setting removes this.
  • It has not been measured on real voices.

How it decides​

  • They use one fixed, stricter rule, whatever "Names on lines" says. The Names on lines choice (Cautious, Balanced, Eager) on the People screen changes only the names you read. A name you can read on a line does not mean a people-limited automation will fire for it. The People screen says so: "Automations limited to people always use the most cautious rule, whatever is chosen here."

  • They wait for a confident match. The automation waits up to 1.5 seconds after the final line for Earshot to be sure. Automations with no people limit never wait.

  • If Earshot is not sure, the automation does not fire. It was not sure, the voice was not recognised, the line was too short, or the answer came too late. Activity says why, for example:

    "Standby sound" did not fire: voice not recognised
    "Standby sound" did not fire: the voice was Dan, not Priya

  • Safe pressed in between turns a firing into a dry run. Activity says "Safe was pressed before the voice was known".

What can never fire one​

  • A people condition never passes when no voice was heard. Run now, a chained automation, an OSC message, MIDI, a web request or a channel-health event has no voice, so a people-limited automation does not fire for any of them. Activity says "no voice was heard for this trigger". You cannot press Run now to fire one.
  • Typed lines never reach it.
  • Lines from another Earshot computer never reach it.

The Test bench types a phrase with no voice behind it, so it cannot tell you whether a people-limited automation will fire for a real person. Test these by having that person say the line on the real channel, with the show Safe, and reading Activity.

Short lines​

A line needs about a second of real speech before Earshot can tell who spoke. A "go" or a "copy" on its own usually cannot be told. Limit to people only on phrases long enough to recognise: "standby sound cue", not "go".

How it behaved when tried​

On a real host with the show Armed and a local program listening, an automation for the phrase "standby sound cue" on a channel carrying two learned voices fired:

LimitTimes it fired
No people limit5
Limited to the one person whose voice it was5 (every one of that person's lines)
Limited to the other person0

That was with clean computer-made voices.

  • In the engine's own test with the real model, the strict rule was confident on only 1 of 4 lines.
  • On a noisy comms line, measured on test voices, it was confident on 0 to 9 in 100 lines.
  • Nothing has been tried on real crew voices.
What that means in practice

On a real, noisy party line, expect a people-limited automation to stay silent most of the time, even for the right person. It is a filter that errs heavily toward not firing, and it can still fire for a sound-alike. Do not put a cue behind it that the show needs.

Good and bad uses​

UseVerdict
A marker in the Archive when the stage manager says "top of act two"Reasonable. If it does not fire, nothing is lost.
A reminder alert when one named person says "standby"Reasonable, for the same reason.
A lighting cue that must go when the show caller says "go"No. It will often not fire, and "go" is too short to recognise.
Stopping a cue from firing when the wrong person says the wordsNo. A sound-alike can set it off.

For a cue that should only come from one position, limit by channel instead: put the show caller on their own channel and tick that channel under Where to listen. A channel limit does not depend on recognising a voice.

More about where the voice numbers come from is in Limits and known behaviour.
