Recipes

Ten complete automations. Each one lists every field to fill in, in the order the editor shows them, so you can build it exactly as written. Change the names, channels and addresses to suit your show.

Read this before you copy anything
  • None of these has been run against a real console, desk or video server. Earshot's show-control path has been exercised only against stand-ins on one Mac. See Limits and known behaviour.
  • The device addresses are not Earshot's. Addresses such as /eos/cue/…/fire and /cue/…/start belong to the receiving product. Check each one against that product's own documentation, and check its OSC port and whether its OSC input is switched on.
  • Every action is a dry run while the show is Safe. That includes alerts, markers, typed text and flags. Nothing in these recipes does anything real until the show is Armed.
  • Rehearse every one with the routine in Testing before you rely on it.

The channel, group and destination names below are the mock show's ("Spring Tour at Harbour Hall"): channels Show Caller, Stage Manager, Deck Left and so on, the group Stage, and two OSC destinations.

Before you start: two destinations​

Several recipes send OSC. Make the destinations first: in any Send OSC action press Manage destinations, then Add a destination.

NameHostPortProtocol
Eosyour lighting desk's address, for example 10.0.1.20the desk's OSC receive port, for example 8000UDP
QLabyour QLab computer's address, for example 10.0.1.3053000UDP

The two destinations. The addresses are made up. Mock show, not a real show.

1. Lighting: "go cue forty two"​

The show caller says a cue number, and the lighting desk fires that cue.

PartFieldValue
BasicsNameGo cue
WhenThis automation starts when itA spoken phrase
WhenMatch modeExact phrase
WhenPhrase 1go cue {number}
WhenWhere to listen: ChannelsShow Caller
Only if(none)
Then1. Send OSC: DestinationEos
Then1. Send OSC: Address/eos/cue/{{capture.number}}/fire
Then1. Send OSC: Arguments(none)
Then2. Add a marker: Marker textCue {{capture.number}}
SafetyCooldown (milliseconds)2000
SafetyFire onFinal text (recommended)
Said on Show CallerResult
"Go cue forty two."Sends /eos/cue/42/fire. Adds the marker "Cue 42".
"Go Q 7."Sends /eos/cue/7/fire.
"Standby cue forty two."Nothing. The word "go" is not there.
"Go cue 7 and 8."Nothing. Activity: "Go cue" did not fire: the number may be incomplete: …
"Go cue forty two" on Stage ManagerNothing. Only Show Caller is ticked.

Activity shows Fired Go cue: phrase "…" on Show Caller when Armed, or Would have fired Go cue: … with Dry run when Safe.

Watch for

  • If your callers say "lighting cue forty two, go", write the phrase that way: lighting cue {number} go. Then "Standby lighting cue forty two" cannot fire it, because no "go" follows the number. In the one full run of the cue path, "Lighting cue 42, go." sent exactly one OSC message with the number 42, and the "Standby…" lines sent nothing.
  • A point cue arrives as 12.5. Check your desk accepts that in an address.
  • Read How Earshot hears numbers for what is refused.

Watch for

  • {n} catches one word, whatever it is. "Sound cue next go" would send /cue/next/start. If your cue numbers are always digits, use recipe 5's pattern style to accept digits only.
  • QLab's cue number is what goes in the address, not its position in the list. Check QLab's documentation for the address and for how to allow OSC control.

3. A blackout call that also alerts everyone​

Anyone on a stage channel calls a blackout. The desk fires a macro, and every screen shows a red banner until an operator acknowledges it.

PartFieldValue
BasicsNameBlackout
WhenThis automation starts when itA spoken phrase
WhenMatch modeAny of
WhenWords or phrasesblackout and kill the lights
WhenWhere to listen: GroupsStage
Only if(none)
Then1. Send OSC: DestinationEos
Then1. Send OSC: Address/eos/macro/99/fire
Then2. Flash an alert: Alert textBLACKOUT called by {{channel.name}}
Then2. Flash an alert: Colour#ff4639
Then2. Flash an alert: Length of one flash (ms)1500
Then2. Flash an alert: Flashes3
Then2. Flash an alert: Stay on screen until someone acknowledgesOn
Then2. Flash an alert: Show to(none ticked: everyone)
SafetyCooldown (milliseconds)5000
SafetyFire onFinal text (recommended)

The alert, waiting to be acknowledged. Mock show, not a real show.

Activity shows Fired Blackout: phrase "…" on Deck Left.

Watch for

  • A single word fires wherever it is said. "We go to blackout after the song" on a Stage channel fires this. Matching is on whole words anywhere in the line. For anything that matters, use a longer phrase that nobody says in passing.
  • Operators and admins get the Acknowledge button. It clears the alert on every screen at once.
  • The macro number is an example. Use your own.

4. A marker at "top of act two"​

Markers make the Archive easy to find your way round afterwards. This one costs nothing if it misfires.

PartFieldValue
BasicsNameAct two marker
WhenThis automation starts when itA spoken phrase
WhenMatch modeExact phrase
WhenPhrase 1top of act two
WhenWhere to listen: ChannelsShow Caller
Only if(none)
Then1. Add a marker: Marker textTop of act two
SafetyCooldown (milliseconds)60000
SafetyFire onFinal text (recommended)

Activity shows Fired Act two marker: phrase "…" on Show Caller. The marker appears in the Archive.

Watch for

  • It also fires on "Standby top of act two, everybody please", because those four words are in that line. For a marker that hardly matters. For a cue it would. The one-minute cooldown stops the "go" a few seconds later from adding a second marker.
  • To mark every cue instead, add an Add a marker action to your cue automations, as recipe 1 does.

5. A video server by web request, then a follow-up OSC​

"Video four, go" tells a video server to play clip 4 by web request, waits half a second, then starts the matching QLab cue.

PartFieldValue
BasicsNameRoll video
WhenThis automation starts when itA spoken phrase
WhenMatch modeRegular expression
WhenPatternvideo (?P<n>\d+) go
WhenWhere to listen(all empty: every channel)
Only if(none)
Then1. HTTP request: MethodPOST
Then1. HTTP request: URLhttp://10.0.1.40:8080/play/{{capture.n}}
Then1. HTTP request: HeadersAuthorization, with your server's key as the value
Then1. HTTP request: Body(empty)
Then2. Wait: Wait (milliseconds)500
Then3. Send OSC: DestinationQLab
Then3. Send OSC: Address/cue/{{capture.n}}/start
SafetyCooldown (milliseconds)2000
SafetyFire onFinal text (recommended)

These three actions in the editor. Mock show, not a real show.

SaidResult
"Video four, go."POST to http://10.0.1.40:8080/play/4. Half a second later, /cue/4/start to QLab.
"Video playback go."Nothing. \d+ accepts digits only.

Activity shows Fired Roll video: phrase "…" on Video, with the web request shown as POST and the host only.

Watch for

  • The pattern is matched against tidied text, where spoken numbers are already digits. Write \d+, never "four".
  • The header value is a secret. Once saved it shows as •••• (unchanged). It is not copied when you duplicate the automation and not included in a show file. After an import this automation arrives switched off until you enter the URL and the header value again.
  • If Make safe is pressed during the Wait, the OSC is never sent. If the web request has already arrived at the server, Safe cannot recall it.
  • The web request must answer within a few seconds or it counts as failed. The OSC still goes: one failed action does not stop the next.
  • The URL and port are examples. Use your server's own API.

6. An alert when an audio device is lost​

If an interface is unplugged or stops delivering audio, tell the operators at once.

PartFieldValue
BasicsNameAudio device lost
WhenThis automation starts when itA channel's health
WhenChannelAny channel
WhenWhen itDevice lost
Only if(none)
Then1. Flash an alert: Alert textAudio lost on {{channel.name}}
Then1. Flash an alert: Colour(empty)
Then1. Flash an alert: Length of one flash (ms)2000
Then1. Flash an alert: Flashes2
Then1. Flash an alert: Stay on screen until someone acknowledgesOn
Then1. Flash an alert: Show toOperators and Admins
SafetyCooldown (milliseconds)2000
SafetyFire on(ignored: only spoken phrases use it)

Activity shows Fired Audio device lost: device lost.

Watch for

  • The alert only appears while the show is Armed. In Safe this is a dry run like everything else, and you get only a Would have fired row in Activity. The channel's own badge (No input, Offline or Error) shows in any state: see status and badges.
  • It never fires for a channel that comes from another Earshot computer.
  • Make a twin with When it set to Recovered and the text Audio back on {{channel.name}}.
  • Unplugging a USB interface mid-show is untested.

7. A console button that sends text into a channel​

A button on the lighting desk sends /desk/standby. Earshot writes a line into the Stage Manager channel for everyone to read.

PartFieldValue
BasicsNameDesk standby
WhenThis automation starts when itAn incoming OSC message
WhenOSC address pattern/desk/standby
Only if(none)
Then1. Send text to a channel: Send toA fixed channel
Then1. Send text to a channel: ChannelStage Manager
Then1. Send text to a channel: TextLighting desk: STANDBY
SafetyCooldown (milliseconds)1000
SafetyFire on(ignored)

Then let the console in, under Setup, Show control:

  1. Turn on Controllers may send OSC to Earshot.
  2. Under What incoming OSC may do, choose Trigger automations and press Apply.
  3. Under Devices allowed to control, add the console's IP address.
  4. Point the console at this computer's address and the UDP port shown (4781 unless you changed it).

See OSC input.

Activity shows an incoming OSC row for /desk/standby, then Fired Desk standby: OSC /desk/standby. The line in the channel has the Typed badge and the author "Automation: Desk standby".

Watch for

  • The line it writes is a typed line, so it can never fire a phrase automation.
  • To pass a value, use a capture: the pattern /desk/page/{page} with the text Lighting desk: page {{capture.page}}. An argument on the message is {{osc.args.0}}.
  • The runaway stop applies. A console that sends this more than 20 times in 10 seconds while Armed stops the automation. See Problems and the runaway stop.
  • A UDP sender's address can be forged by anyone on the same network. Use the TCP port for anything that matters.
  • Refused OSC is logged in Activity with the reason, for example "this source is not allowed to trigger".
  • If you only need a line of text and no other action, a console can send /earshot/channel/<channel>/send with the text as its argument, with no automation at all. See the OSC address reference.

A pad on a MIDI controller runs the "Standby chime" automation, which other triggers can share.

Tick the controller's port under Setup, Show control, MIDI input ports, or Earshot is not listening to it. If you plugged the controller in after Earshot started, press Refresh there first. See MIDI.

Activity shows an incoming MIDI row, Fired Pad 1 standby: MIDI … on <port>, then Fired Standby chime: chained (hop 1).

Watch for

  • "Standby chime" keeps its own cooldown. Two pads pressed within its 2 seconds flash it once.
  • MIDI is not covered by the runaway stop. A device that echoes MIDI back can fire this about ten times a second until you make the show Safe.
  • A chain runs each automation at most once, at most 32 firings in all, and at most 8 deep.
  • MIDI has been tried only against stand-ins, never on a real controller.

9. A web request that marks "show start"​

A button in another system (a show-control page, a script, a phone shortcut) calls an address, and Earshot drops a marker.

PartFieldValue
BasicsNameShow start (web)
WhenThis automation starts when itA web request
WhenPathPress Generate new path
Only if(none)
Then1. Add a marker: Marker textShow started: {{var.body}}
SafetyCooldown (milliseconds)2000
SafetyFire on(ignored)

Before you save, press Copy URL. The address is shown only now. Then call it with POST, using the host's address from Setup, Access:

curl -X POST http://192.168.1.20:4780/api/v1/webhooks/YOUR-PATH-HERE -d "from the SM desk"

That adds the marker "Show started: from the SM desk". With no body, the marker reads "Show started: ".

Activity shows Fired Show start (web): webhook. Admins also see the path there; everyone else sees only "webhook".

Watch for

  • The address is a password. Whoever has it can fire this automation in any access mode, without signing in.
  • It still obeys Armed and Safe. Called while Safe, it is a dry run and no marker is added.
  • The path cannot be read back after saving. If you lose it, generate a new one. The old address stops working.
  • The runaway stop applies: more than 20 real firings in 10 seconds stops it.
  • After a show-file import it arrives switched off, needing a new path.
  • Web requests have been tried only against stand-ins. See The HTTP API.

10. A flag as an interlock: "only in show mode"​

You do not want "go cue…" to fire during the half-hour call or a notes session, even if someone has armed the show. A flag makes the cue wait until the stage manager has said "show mode".

It takes three automations.

A. Turn show mode on

PartFieldValue
BasicsNameShow mode on
WhenThis automation starts when itA spoken phrase
WhenMatch modeExact phrase
WhenPhrase 1we are in show mode
WhenWhere to listen: ChannelsStage Manager
Then1. Set a flag: Flag nameshow-mode
Then1. Set a flag: Set it toSet
Then2. Flash an alert: Alert textSHOW MODE: cues are live
SafetyCooldown (milliseconds)2000

B. Turn show mode off

PartFieldValue
BasicsNameShow mode off
WhenThis automation starts when itA spoken phrase
WhenMatch modeExact phrase
WhenPhrase 1we are out of show mode
WhenWhere to listen: ChannelsStage Manager
Then1. Set a flag: Flag nameshow-mode
Then1. Set a flag: Set it toCleared
Then2. Flash an alert: Alert textShow mode off
SafetyCooldown (milliseconds)2000

C. The guarded cue

Build recipe 1, and add one condition:

PartFieldValue
Only ifKind of conditionA flag is set
Only ifFlag nameshow-mode

Type the flag's name exactly the same in all three.

What happensResult
Armed. Caller says "go cue forty two" before show mode.Nothing sent. Activity: "Go cue" did not fire: condition not met: flag show-mode is not set
Armed. Stage manager says "we are in show mode".The flag is set. The alert shows.
Armed. Caller says "go cue forty two"./eos/cue/42/fire is sent.
Stage manager says "we are out of show mode".The flag is cleared. Cues wait again.

Watch for

  • A flag is only really set while the show is Armed. In Safe, "Set a flag" is a dry run, so saying "we are in show mode" while Safe does not set it. Arm first, then say it.
  • Flags start cleared every time Earshot starts. After a restart, say "we are in show mode" again.
  • A flag is not a second Safe. It guards only the automations that have the condition. Make safe is still the way to stop everything.
  • The two phrases are deliberately long, so nobody says them in passing.
  • There is no screen that shows a flag's state. The alerts in A and B are how the crew knows. If you are unsure, say the "on" or "off" phrase again.

Adapting a recipe​

  • Different words. Change the phrase, then prove it with the rehearsal routine. If the recogniser keeps mis-hearing a word, add the mis-hearing as another phrase.
  • Several positions. Tick more channels, or a group, under Where to listen.
  • Several things at once. Add more actions. They run in order. Use Wait between them if the order must be spaced out.
  • The same actions from several triggers. Put the actions in one Manual only automation, and have each trigger Run another automation, as recipe 8 does. Remember the second automation sees values as {{var.capture.number}}, not {{capture.number}}: see Variables.

Every field used here is described in Triggers and conditions and Actions.
