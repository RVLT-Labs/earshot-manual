Actions

This page is the reference for the Then part of the automation editor ("What happens, in this order.") and for the Safety part beneath it.

Actions run in order, top to bottom. To add one, choose its kind in the box at the bottom of Then and press Add action. The arrows on an action move it up and down, and the bin removes it. An automation with no actions can be saved, with the note "With no actions this does nothing when it fires."

Three actions in order, on the mock show's "Roll video" automation. Mock show, not a real show.

Actions really send only while Armed

While the show is Safe, every action is a dry run: Earshot logs what it would have done and sends nothing. That includes the actions that stay inside Earshot, such as adding a marker or setting a flag. See Safe and Armed.

Most text fields accept {{variables}}, such as {{capture.number}}. Pick one from Insert variable… under the field, or type it. See Variables.

Send OSC​

Sends one OSC message to a destination.

FieldWhat it is
DestinationWhere it goes. Listed as, for example, Eos (UDP 10.0.1.20:8000). Manage destinations opens the list.
AddressThe OSC address. "Must start with /." Accepts variables.
ArgumentsNone by default ("No arguments: a bare message."). Add an argument adds one.

The address and variables​

A value put into an address by a variable may not contain / * ? [ ] { } , # or a space. If it does, or if the variable is empty, that action is skipped and the reason is logged. It is never tidied up and sent anyway. This is what stops a mis-heard word from turning /eos/cue/{{capture.number}}/fire into an address that hits every cue.

The parts of the address you typed yourself are not restricted.

Arguments​

Each argument has a type and a value. The value accepts variables.

Type in the editorValueExample
Whole numberA whole number that fits 32 bits.1 or {{capture.number}}
Decimal numberA decimal number.0.5
TextAny text.go
True / falsetrue, false, 1 or 0.true
Nothing (nil)No value.
Impulse (bang)No value.
Raw bytesHex bytes.0A FF 10

If a value cannot be read as its type when the automation fires, the action is skipped and Activity says why. Earshot never substitutes a default. For example, a Whole number argument set to {{capture.number}} is skipped when someone says "cue twelve point five", because 12.5 is not a whole number. Use Decimal number if you expect point cues.

OSC destinations​

A destination is a device that receives OSC: "a lighting desk, a video server, a QLab machine". Destinations belong to the show, so every automation can use them.

OSC destinations. The addresses are made up. Mock show, not a real show.

Press Manage destinations, then Add a destination:

FieldWhat it is
NameWhat you call it, for example Eos.
HostThe device's address, for example 192.168.1.20.
PortThe port the device listens on for OSC.
ProtocolUDP or TCP. Use what the device expects.

The list shows how many automations use each destination. Deleting one that is in use leaves those actions with a problem: "That OSC destination no longer exists. Pick another, or add it again."

UDP or TCP matters when you press Safe:

  • A UDP message is gone the moment it is sent.
  • OSC waiting for a TCP destination is discarded when you press Safe. A TCP destination that is down is retried, and the sends skipped meanwhile are logged.

Editing one destination reconnects only that destination. Pressing Safe resets all of them.

Send MIDI​

FieldWhat it is
Output portThe MIDI output to send to. A port that has gone is listed as "(not found)".
Message typeNote on, Note off, Control change, Program change or Raw bytes.
MIDI channel (1 to 16)For every type except Raw bytes.
Note and VelocityNote on. 0 to 127 each. A new action starts at note 60, velocity 100.
NoteNote off. 0 to 127.
Controller and ValueControl change. 0 to 127 each.
ProgramProgram change. 0 to 127.
Raw bytes (hex)"Like 90 3C 7F: status byte, then data bytes."

The number fields accept variables, so a MIDI trigger can pass its own note on: {{midi.note}}. The result must be a whole number from 0 to 127, or the action is skipped.

A MIDI send is on time or it does not go. If the port is busy for more than 1 second, the send is dropped and Activity says "not sent: the MIDI port was busy for more than 1 s".

HTTP request​

Calls a web address: a video server, a show-control system, a chat hook.

FieldWhat it is
MethodGET, POST, PUT or DELETE.
URL"Starts with http:// or https://. Variables in the URL are made URL-safe for you."
HeadersOptional. Add a header adds a name and a value.
Body"Optional. Sent as written, with variables filled in (not URL-encoded)."
  • A variable in the URL is percent-encoded, so a ?, & or # in something that was said cannot change the request. A variable in the Body is put in as it is.
  • The request must finish within a few seconds or it counts as failed. At most 5 redirects are followed.
  • Pressing Safe cancels a request in progress, and any redirect is not followed.
  • Earshot does not use a proxy for these requests, even if the computer has one set.

Header values are secrets​

A header value usually holds a key or a token, so Earshot treats every header value as a secret:

  • Once saved, the value is never sent back to any browser. The editor shows •••• (unchanged) with a Replace button.
  • Leave it alone to keep it. Press Replace and type a new value to change it.
  • A duplicated automation does not get the values: "Secrets are not copied. Re-enter 1 header value."
  • An exported show file hides header values and cuts web addresses back to the host name. After an import those automations arrive switched off until you enter them again.
  • Operators and viewers do not see the URL's path, the body or the header values. In Activity everyone sees only the method and the host.

See saved secrets.

Run a shell command​

Runs a command on the host computer, with the rights of the account Earshot runs under.

Off unless an admin turns it on

Shell commands do nothing unless an admin turns on Setup, Show control, Allow automations to run shell commands. Until then the action is skipped, and the editor says "Shell actions are switched off in Setup, so the engine will skip this one until an admin enables them."

Importing a show file never turns the switch on, and every automation with a shell action arrives switched off after an import, whatever this computer's setting. Read what a command does before you switch it on.

One field, Command. "Runs on the machine that hosts Earshot, only if an admin has enabled shell actions in Setup. This is not a template."

A shell command cannot contain {{…}}. A command with one is refused. Values reach the command as environment variables instead, "so spoken text can never become part of the command itself". The name is the variable's name in capitals, with every other character turned into _, after EARSHOT_:

VariableEnvironment variable
{{text}}$EARSHOT_TEXT
{{match}}$EARSHOT_MATCH
{{capture.number}}$EARSHOT_CAPTURE_NUMBER
{{channel.name}}$EARSHOT_CHANNEL_NAME
{{osc.args.0}}$EARSHOT_OSC_ARGS_0
{{var.body}}$EARSHOT_VAR_BODY

The editor lists the ones your trigger provides under the field. If you paste an old command with {{text}} in it, the button Use environment variables instead rewrites it for you.

An example, for a Mac:

say "$EARSHOT_TEXT"

Always put the variable in double quotes, as above, so a value with spaces stays one value.

Things to know:

  • The command gets a nearly empty environment: the EARSHOT_ values, and PATH, HOME and the temporary-folder variables. Nothing else from Earshot's own environment is passed on.
  • Its output is thrown away. Earshot only records whether it ran.
  • A command may run for 5 seconds. After that it is stopped, together with the programs it started. A cue that needs longer must start its own long-running program.
  • Pressing Safe stops a running command and the programs it started. That is untested on Windows.
  • Activity shows "run a shell command", never the command text, because a command line often carries a password.

Flash an alert​

Puts a large banner across Earshot's screens. Use it for things people must not miss.

The mock show's Blackout automation. Not a real show.

An alert that stays until someone presses Acknowledge. Mock show, not a real show.

FieldWhat it is
Alert text"Shown in large type across every screen." Accepts variables. A new action starts as {{text}}, the whole line that was heard.
Colour"A hex colour like #ff8800. Empty uses the theme's attention colour."
Length of one flash (ms)A new action starts at 3000. Under 400 ms "is shown as a steady banner, not a flash, to avoid strobing".
FlashesHow many times. A new action starts at 3. With 0, nothing is shown.
Stay on screen until someone acknowledges"Operators and admins get an Acknowledge button; it clears on every screen at once."
Show toViewers, Operators, Admins. "Leave all unticked to show it to everyone."

"Flashing is slow (at most about 2.5 times a second), and people who ask their device to reduce motion see a steady banner instead."

Play a sound, and Show or hide the window​

These two do not run in this build

You can add Play a sound and Show or hide the window, but they do nothing. The automation shows a problem saying so ("'Play sound' is not available in this build; the other actions still run."). The other actions in the same automation still run.

Send text to a channel​

Writes a typed line into a channel, as if someone had typed it.

FieldWhat it is
Send toA fixed channel or A channel worked out when it runs.
ChannelFor a fixed channel: pick it.
Channel name, short name or numberFor a worked-out channel. "Looked up by name, then short name, then position (1 is the first channel)." Accepts variables. A new one starts as {{channel.slug}}, the channel the trigger came from.
TextWhat to write. Accepts variables.

The line appears with the Typed badge, and its author reads "Automation: " followed by the automation's name. A typed line never fires a phrase automation, so this cannot loop.

If the channel cannot be found, or the text comes out empty, the action is skipped.

Add a marker​

One field, Marker text. "Appears on the timeline in the Archive." Accepts variables. A new action starts as {{text}}.

Markers let you jump to a moment later: "Cue 42", "Top of act two". See Archive and markers.

These are never sent to phones, tablets or other computers. They do nothing while someone at the host is in Setup, Automations, Archive or Activity, so a cue never throws someone out of an editor. The same controls are available by OSC: see the OSC address reference.

Pause or resume a channel​

FieldChoices
ChannelThe channel.
DoPause it or Resume it.

A paused channel shows the Paused badge until it is resumed. See status and badges.

Clear the transcript​

One field, Channel: Every channel or one channel. "Clears what is on screen and in this session's live transcript."

Clearing also removes saved audio

Clearing a transcript makes the saved audio behind those lines unreachable at once, and deletes the files. See Replay a line's audio.

Set a flag​

FieldWhat it is
Flag nameAny name. "Conditions can check it."
Set it toSet or Cleared.

A flag is an on/off marker that only automations use. One automation sets it; another has an Only if condition, "A flag is set" or "A flag is not set", that checks it. See Triggers and conditions and the interlock in Recipes.

Flags start cleared each time Earshot starts. A flag is only really set while the show is Armed: in Safe, this action is a dry run like any other.

Wait​

One field, Wait (milliseconds). "Actions after this one run later. 1000 is one second." A new action starts at 500.

If Safe is pressed during a Wait, the remaining actions do not run. Arming again later does not resume them.

Run another automation​

One field, Automation: pick which one. "Runs as part of the same moment. A chain runs each automation at most once, and stops after 32 runs in all."

  • The other automation is handed this one's values, with var. in front of each name. {{capture.number}} here is {{var.capture.number}} there, and {{text}} is {{var.text}}.
  • Its own Only if conditions and cooldown still apply.
  • An automation limited to people cannot be run this way: a chain has no voice. See Automations limited to people.

The chain limits, which also break every loop:

LimitValue
Times one automation can fire in a chain1
Firings in one chain, in all32
Depth (one automation running another, running another…)8 hops

Anything past a limit is not run, and Activity says "loop guard: the chain's limit was reached (each automation once per chain, at most 32 firings, 8 hops)". An automation that runs itself gets the warning "This runs itself. An automation fires at most once per chain, so the repeat is skipped."

When an action fails​

One action failing does not stop the ones after it. In Activity the automation's row is marked Failed, and opening the row lists which action was not run (for example "action 1 not run") and the reason. Common reasons:

The reason givenWhat it means
OSC address variable {{capture.number}} = "…" is empty or contains / * ? [ ] { } , # or whitespaceA captured value was not safe to put in an OSC address.
OSC argument 1: "12.5" is not an intThe value does not fit the argument's type.
unknown OSC destination …The destination was deleted.
no channel matches "…"A worked-out channel name matched nothing.
not sent: the show was made SafeSafe was pressed before this action went out.
disarmed during runSafe was pressed while the automation was part-way through its actions. The rest did not run.
not sent: the MIDI port was busy for more than 1 sSee Send MIDI above.
shell actions are disabled (an admin must enable allow_shell_actions)The switch in Setup, Show control, is off. See Run a shell command above.
shell commands cannot contain {{…}}; use the EARSHOT_* environment variablesSee Run a shell command above.

Safety: Cooldown and Fire on​

Safety. Mock show, not a real show.

Cooldown (milliseconds)​

"After it fires, it ignores the trigger for this long. 0 means no cooldown. It always fires at most once per utterance."

  • A new automation has 2000 (two seconds).
  • Set it so that a repeated call does not send the cue twice. A caller who says "go… go" a second apart should send one cue, not two.
  • While it is cooling down, Activity says cooling down (N ms left).
  • A firing that Earshot refuses (for example because of the runaway limits) still uses up the cooldown.
  • Spoken phrases are exempt from the runaway stop, so Cooldown is the only limit on how often a spoken cue can fire.

Fire on​

ChoiceWhat it does
Final text (recommended)Waits for the finished line. A channel that is Behind fires later.
Draft text (faster, less safe)Can fire while the person is still speaking, as soon as the draft matches and at least one more word has followed. Draft text can still change, so a mis-hearing that Earshot would have corrected can fire.

Either way an automation fires at most once per line. In the list, an automation set to draft text is marked "fires on draft text".

"Only spoken phrases use this; other triggers ignore it."

Drafts appear only on channels with "Show words as they are spoken" on, and only while Earshot is keeping up. See channel settings.
