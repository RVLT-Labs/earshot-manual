Showing another Earshot computer's channels

One Earshot computer can show a channel that another Earshot computer is listening to. The channel appears in the Feed, Lanes and Focus on this computer like any other. Only the text crosses: no audio, and no saved clips.

Two words are used on this page:

  • The serving host is the computer that has the audio and does the listening.
  • This computer (the linking host) is the one that shows the other's lines.
What has been tried

Two Earshot hosts were run on one Mac and linked over plain http through the real screen. Not tried: two separate computers on a real network, finding each other between machines, a link code on a host that requires one, and https. Treat links as not encrypted. Details are at the end of this page.

Who can do this

Only admins, on both computers.

Step 1: on the serving host​

  1. Open Setup, Channels, the channel, and switch on Shared with other Earshot hosts. Save. Only channels with this switch on can be linked.
  2. If that computer's access mode asks people to sign in (Password or Personal links), make a link code: Setup, Access, People with access, New personal link, with They can set to Viewer. Label it so you know what it is for, for example Broadcast truck link. The link it shows you once is the viewer link to give to the other computer. See Invites and personal links. In Open mode no code is needed.
A link code is an ordinary Viewer link

Whoever has it can open that computer's Earshot as a Viewer and read every channel a Viewer can, not only the shared ones. Treat it like a password. On an unencrypted link it travels readable on the network. To cut a link off for good, revoke it on the serving host, under People with access.

Use a personal link, not a QR invite

The app's own hint reads "On the other host: Setup → Access → invite a Viewer." What the link box accepts is a viewer link of the kind New personal link makes, with token= in it. A QR invite from Invite someone is a different thing: its join link has code= in it, works once in a browser, and is not a link code. A link code on a host that requires one has not been tried end to end.

Step 2: on this computer​

Open Setup, Channels, and press From another Earshot host. It has four steps.

The mock show. "Main stage" and "Broadcast truck" are invented computers.

1. Which Earshot computer?​

Pick one from the list. Each shows its name, its address and a badge, Encrypted or Not encrypted. Look again searches again.

If none are found it says "No other Earshot computers were found on this network. If you know the other computer's address, type it below." Choose Type an address and fill in Address and Port (4780 unless the other computer was started on another).

You can paste a whole viewer link into Address. Earshot takes it apart: the address and port stay, the code moves to the masked code box, and it says "That was a viewer link. Its address and port are filled in here, and its code is in the Link code step."

2. How should it connect?​

ChoiceThe app says
Encrypted (https)"Encrypted links have not been proven end to end in this build, and need a certificate this computer trusts."
Not encrypted (http)"Lines and the link code travel readable on this network."

See Encrypted or not below. In practice, choose Not encrypted (http) on a network you trust.

3. Link code​

Link code (optional): "On the other host: Setup → Access → invite a Viewer. Whoever has this code can read everything a Viewer can on that host, so treat it like a password."

"Paste the code, or a whole viewer link: Earshot keeps only the code. Leave it empty if the other computer does not ask for one."

If you paste a link that belongs to a different computer from the one you chose, the box says "This link is for another computer than the one you chose."

Press Find channels.

4. Choose channels​

The screen names the other computer and its address, says "Reached over an encrypted connection." or "Reached without encryption.", and lists the channels it shares.

  • Tick the ones you want and press Add selected channels.
  • A channel you already have says "Already added".
  • If there are none: "That computer shares no channels. On it, turn on “Shared with other Earshot hosts” for a channel."
  • Each result reads "Added name." If some fail, Try the failed ones again.

The channels now appear in your channel list with a link icon, and their lines start arriving.

What a linked channel can and cannot do​

A linked channel…
is read-onlyNobody can type into it from here.
is never shared onwardThis computer cannot offer it to a third one. Links never chain.
never fires automations hereIts lines are never matched against a phrase, and a Silence trigger never applies to it. A Silence trigger that listens only to linked channels is reported as a problem: "Silence triggers do not work on channels from another host."
has no level meterThere is no audio here.
has none of the audio settingsNo saved audio, voice recognition, profanity filter, engine or speech detection. Those are fixed by the serving host.
is markedA link icon and "from address". If it is not encrypted it also carries a Not encrypted mark: "Lines from this host travel unencrypted on the network."
is stored and searched hereIts lines go into this computer's sessions, and can be searched, exported and translated like any line.
does not carry namesNames of recognised speakers stay on the serving host. A typed line keeps the name of whoever typed it.

At most 32 channels can share one link (one address with one code). More than that is refused.

A linked line arrives as the text the serving host's readers see. The original of a line that was changed there (by its glossary, a number or a show word) does not come across, so a linked line has no pencil here.

The status line​

Under a linked channel in Setup, Channels, Earshot says what is happening, in these words:

The status lineMeaning
"Connecting to address (not encrypted)."It is trying to reach the other computer.
"Linked to name at address (not encrypted). 10 lines received."Working. It adds ", N dropped" if some lines were dropped.
"Cannot reach name or address: reason. Retrying."The other computer or the network is down. Earshot keeps trying.
"address refused the link: …"The other computer said no, for example because the channel is no longer shared.
"The link code was refused. Check the code on the other host, then enter it in this channel again (or switch the channel off and on)."See A refused link code.
"This is this host itself …"The address you gave is this computer. A computer cannot link to itself.

The other computer's address is shown next to its name because a computer can call itself anything.

The mock show with three invented linked channels: one working, one whose code was refused, and one that cannot be reached.

In the channel list and the Feed, a linked channel's badge follows the link: Starting while connecting, listening while linked, Error when the other computer refused, and Offline when it cannot be reached. See Status and badges.

When the other computer goes away and comes back​

  • The status says "Cannot reach …" and Earshot keeps trying, waiting a little longer each time, up to about half a minute between tries.
  • When the other computer returns, the link comes back by itself, and Earshot catches up on what it missed if it can.
  • If lines may be missing, a line appears in that channel: "Link to name was down for N s; some lines may be missing".
  • The first link after this computer restarts begins from "now", without that notice.
  • A dead link never slows this computer's own channels.
  • A link never brings across lines from before the channel was shared, or from a time when sharing was switched off.

If the serving host stops sharing the channel, deletes it or leaves, the link ends at once.

A refused link code stops the link​

If the serving host refuses the code, Earshot does not try again. This is on purpose: every retry would count as a wrong guess on the other computer, and enough of those would lock this computer out of it.

The link stays stopped until one of these happens:

  • the channel is saved again on this computer,
  • the channel is switched off and on, or
  • Earshot on this computer is restarted.

Fixing the code on the serving host alone does not bring it back. Open the channel here, enter the code under New link code, and save.

Changing a linked channel later​

Open the channel in Setup, Channels. Under "Where this channel comes from" you can change the Address, the Port, how it connects, and the code.

A linked channel in the mock show. The other computer's name and address are invented. A linked channel has none of the audio settings.

  • "A link code is saved. Leave the box empty to keep it." A saved code is never shown. See Saved secrets.
  • Remove code removes it when you save ("The link code will be removed when you save."). Keep code undoes that.
  • "Changing the address, port or encryption clears the stored link code. Enter it again."
  • An address with a code must say how it connects: Encrypted or Not encrypted.

Switching the channel's Enabled switch off stops showing new lines from the other computer. Deleting it ends the link for that channel.

Encrypted or not​

Choose Not encrypted (http) and "Lines and the link code travel readable on this network."

Choose Encrypted (https) and the app says "Encrypted links have not been proven end to end in this build, and need a certificate this computer trusts."

That is the honest position:

  • https links have never been tried between two computers.
  • Earshot has no setting to give its own address a certificate, so a serving host normally offers plain http only.
  • A serving host with a self-signed certificate fails unless this computer trusts it.

Use plain http on a network you trust, and treat the link code as readable by anyone on it.

Example: the truck reads the stage's Show Caller​

The stage rack ("Main stage") hears the Show Caller channel. The broadcast truck runs its own Earshot and wants those lines next to its own channels.

On Main stage

  1. Setup, Channels, Show Caller: switch on Shared with other Earshot hosts, Save changes.
  2. Main stage is on Personal links, so make a code: Setup, Access, New personal link, Who is it for? Broadcast truck link, Viewer, Make link. Press Copy link. It is shown once.
  3. Send the link to the truck privately.

On the truck

  1. Setup, Channels, From another Earshot host.
  2. Pick Main stage from the list, or choose Type an address and paste the whole link into Address.
  3. Choose Not encrypted (http).
  4. If you did not paste the link in step 5, paste it into Link code (optional). Press Find channels.
  5. Tick Show Caller and press Add selected channels. "Added Show Caller."
  6. Check its status line reads "Linked to Main stage at … (not encrypted)."

The truck now sees Show Caller's lines live. Its own automations ignore them.

After the show, on Main stage, press Revoke next to "Broadcast truck link". The link stops within a second.

What has been tried​

Two Earshot hosts were run on one Mac and linked through the real screen:

  • The channel's lines, including drafts, appeared live.
  • Stopping the serving host gave "Cannot reach … Retrying." within about 2 seconds.
  • It relinked 12 seconds after the serving host returned, and a gap line appeared ("down for 67 s").

Not tried: two separate computers on a real network, discovery between machines, a link code on a host that requires one, and https.

Also known:

  • A linked channel does not say when its last line arrived.
  • A computer can call itself anything, which is why the address is shown beside the name.
  • The first link after this computer restarts has no gap notice.
