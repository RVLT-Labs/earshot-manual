What happens when the host restarts

Sooner or later the Earshot computer restarts mid-rehearsal: a power dip, an update, someone quitting the wrong program. This page says exactly what happens, so you know what to check first.

The short version: the show comes back Safe, a new session starts, people on the shared password must sign in again, and people on personal links carry on.

Who is affected, and what they must do​

Who or whatWhat happensWhat they must do
Every phone and browserShows "Reconnecting", then if it goes on, "Can't reach the Earshot computer". It keeps trying by itself.Nothing. It reconnects when the host is back.
People who signed in with the passwordSigned out. Password sign-ins are kept only in the host's memory.Type the password again.
People with a personal linkStill let in. Personal links are kept by the host on disk.Nothing.
Someone holding a QR invite they had not used yetThe code no longer works.Ask the operator for a new one.
The desktop app's own windowSigned in as an admin automatically, as always.Nothing.
An admin using the Admin: address from earshotdThe token in that address is new every time the program starts, unless it was started with --admin-token. The old address stops being an admin's.Use the new Admin: address the program prints.
The operator at the Armed controlArmed is forgotten. The show comes back Safe, unless Setup, Show control, Start armed is on.Decide whether to arm again. Nothing fires until you do.
The transcriptA new session starts. The old one is in the Archive.Nothing. Use the Archive to read back.
Anything said while the host was downIt was not written down. Earshot cannot recover speech it did not hear.Nothing can be done.
Channels from another Earshot computerThe links connect again by themselves. The first link after this computer restarts begins from "now", with no "some lines may be missing" notice. A link that had stopped because its code was refused is tried again.Check each status line reads "Linked to …".
Another Earshot computer reading this one's channelsIt says "Cannot reach …" and keeps trying, then links again by itself and writes "Link to name was down for N s; some lines may be missing" in the channel.Nothing.
Cloud speech and translation countersStart again from zero. They are "Counted since Earshot started".Nothing.
Saved audioKept. The age and size limits are checked again as Earshot starts.Nothing.

What is kept​

Everything you set up is on disk and comes back as it was:

  • The show: channels, groups, automations, OSC destinations, the glossary, people and their learned voices.
  • This computer's settings: who can connect and the password, OSC and MIDI input, cloud keys, saved-audio limits, Start armed.
  • Every past session, its markers, and saved audio within the limits.
  • Personal links.
  • Downloaded models.

What is forgotten​

  • Armed. The show is Safe again.
  • Password sign-ins.
  • Unused QR invites.
  • The live session. A new one begins.
  • An earshotd admin token that was not fixed with --admin-token.

A phone that only lost the network​

This is different from the host restarting. If a phone walks out of Wi-Fi range and back, or drops for a moment:

  • It shows "Reconnecting" and keeps trying.
  • When it reconnects, it catches up on the lines it missed.
  • Nobody is signed out. The host never went away.

If the computer sleeps​

Earshot is a program on a computer. If the computer sleeps, Earshot stops listening. Speech during the sleep is not written down, just as if the host were off. Set the host computer not to sleep for the length of the show.

Start armed​

Setup, Show control, Start armed makes automations able to fire as soon as Earshot starts. It is off by default. Leave it off unless the show runs unattended, because with it on, a restart mid-show brings the show back Armed with nobody having chosen that. See Safe and Armed.

After a restart: a two-minute check​

  1. The header says Live and shows the show name you expect.
  2. The header shows Safe. Arm again only if you mean to.
  3. Every channel's level meter moves when someone speaks, with no No input, Offline or Error badge.
  4. If you use the shared password, tell the crew to sign in again. Say the password again if they need it.
  5. If you use channels from another Earshot computer, each status line reads "Linked to …".
  6. If you run headless, note the new Admin: address.
Make restarts boring

Use personal links rather than the shared password, so the crew are not all signed out at once. Start earshotd with a fixed --admin-token so your own address keeps working. See earshotd.

Example: a power dip in the interval​

The rack loses power for ten seconds in the interval and Earshot starts again.

  • The deck crew's phones, on personal links, show "Reconnecting" for a moment and then the Feed again. They see an empty live transcript, because a new session has started.
  • The followspot operators, who typed the password at the half, get the sign-in page. The stage manager repeats the password on comms.
  • The header shows Safe. The automations that fire lighting cues are logging "would have fired" until the stage manager holds Hold to arm again.
  • The first half is in the Archive, under the earlier session.
