  • Saved secrets

Saved secrets are never sent to a browser

Earshot holds a few things that would let someone in, or let them spend your money, if they leaked: the join password, cloud keys, the link codes of channels from other Earshot computers, and two parts of an automation. No browser, not even an admin's, is ever sent one of them. The host sends a marker ("••••") for each secret it holds, and nothing where there is none.

That has one consequence you will meet every day: a saved secret cannot be read back. You can keep it, replace it or remove it. You cannot look at it.

What counts as a secret​

SecretWhere you enter itWhat the screen shows once it is saved
The join passwordSetup, Access, PasswordA Password set badge.
The Deepgram keySetup, Cloud & audioA Key saved badge. "The key is stored on this computer and is never shown again."
The DeepL and Anthropic keysSetup, Cloud & audio, Keys for cloud translatorsA Key saved badge on each.
The link code of a channel from another Earshot computerThe channel, under "Where this channel comes from""A link code is saved. Leave the box empty to keep it."
An HTTP action's header values in an automationThe automation editor, Then, HTTP request, HeadersDots and "(unchanged)", with a Replace button.
A webhook trigger's pathThe automation editor, When, A web requestShown once, when you make it.

Keep, remove or replace​

Every secret box works the same way.

What you wantWhat you doButtons you will see
Keep itLeave the box alone. Saving the rest of the screen does not disturb it.None needed.
Remove itClear it with the button for that.Remove key, Remove code, Clear password
Replace itType a new one and save.Save key, Change password, Replace
  • Leave it alone to keep it. An empty box next to "Key saved" does not mean the key has gone. It means the page was never given it.
  • A saved secret cannot be read back. If you lose a key, get it again from wherever it came from and enter it again.
  • Copy a webhook's address when you create it, because it cannot be shown again. If you lose it, make a new one and update whatever calls it.
  • Personal links are the same. A new link is shown once: "You will not see this again. Copy it or have them scan it now."

What each role can see of your settings​

Admins still need to edit automations, so they see more than everyone else. Nobody sees the secrets themselves.

Viewer and OperatorAdmin
Join password, cloud keys, link codesNothingA marker that one is saved
HTTP header values, webhook pathsHiddenA marker that one is saved
Web addresses in HTTP actionsCut back to the host nameThe whole address
Request bodiesHiddenShown, so they can be edited
Shell commandsHiddenShown, so they can be edited
Learned voicesNever sentNever sent

In the Activity log and in alerts, people who are not admins see a webhook's trigger as just "webhook", without its path. The path is a credential: whoever has it can fire that automation.

An exported show file is hidden the same way, for admins too. See Show files.

Where secrets are kept​

On the host computer, in its data folder:

  • The password is stored as a hash, not as the password.
  • Cloud keys and link codes are stored in the show file there, show.earshot.json.
  • The folder and those files are readable only by your user account (on macOS and Linux).

So the secrets are protected from browsers and from the network, not from someone who can sit down at the host computer and read your files. See Data and files and Privacy.

Logs never contain a secret, and never contain what was said.

Example: rotating the Deepgram key​

The production's cloud account issues a new key every tour leg.

  1. Open Setup, Cloud & audio. The badge under Deepgram API key reads Key saved. The box, Replace the Deepgram key, is empty. That is normal.
  2. Paste the new key and press Save key. "Key saved."
  3. The old key is gone from this computer. There was never a way to read it here.

If the status then reads Key rejected, the new key is wrong. Paste it again and save.

Example: an admin on a second laptop​

The production manager opens Earshot on her own laptop with the Admin: address from earshotd, to tidy up an automation that posts to the video server with an Authorization header.

  • She can read and edit the web address and the body.
  • The header's value shows as dots and "(unchanged)". She saves her edit without touching it, and the stored value is kept.
  • If she needs to change the value, she presses Replace and types the new one. She still cannot see the old one.

What was checked​

On a real host, an admin's view of the settings showed a stored key as "••••". Saving settings with the marker in place kept the real key on disk, and the marker itself was stored nowhere.
