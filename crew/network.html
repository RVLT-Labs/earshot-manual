Network

This page covers the Network panel at the bottom of Setup, Access, and the rules about which web addresses Earshot answers to. Most shows need none of it: give the crew the address under Address for the crew and carry on.

Who can do this

Only admins change these settings. The command-line options on this page are for whoever starts earshotd.

Announce on the network (Bonjour)​

Announce on the network (Bonjour) "Lets other Earshot computers on this network find this one." It is on by default.

What it is for: when another Earshot computer wants to show one of this computer's channels, its link screen lists the Earshot computers it can find, so nobody has to type an address. See Showing another Earshot computer's channels.

What it announces: this computer's Earshot name, its version, its access mode (Open, Password or Personal links) and whether it uses https. Nothing about the show, its channels or the transcript.

What it is not: it is not how crew phones find Earshot. Phones use the address you give them.

Turn it off if you do not want this computer to be discoverable. Linking still works by typing the address.

Earshot does not announce itself at all when it listens only on the computer itself (for example earshotd --bind 127.0.0.1).

Name shown to others​

Name shown to others: "Crew see this when they join. Leave it empty to use this computer's name."

The name appears:

  • On the sign-in and join pages, as "Join" and the name, so people can tell they have the right computer.
  • In other Earshot computers' lists of what is nearby.
  • On a channel linked from this computer, on the other computer's screen.

Type a name such as FOH Rack and press Save name. The screen says "Name saved."

If you leave it empty, the computer's own system name is used. If that name cannot be used on the network (it is empty, has odd characters or spaces, or is too long), Earshot calls itself "earshot".

A name is only a label

Any computer can call itself anything. That is why Earshot shows a linked computer's address next to its name. Do not trust a name on its own.

Other Earshot computers nearby​

Under Other Earshot computers nearby, Earshot lists what it found on the network. Each entry shows the computer's name, its access mode, its address and port, and its version, for example:

Main stage · Password · 192.168.1.31:4780 · Version 0.1.0

Look again searches again. A search takes a second or two. If nothing is found: "No other Earshot computers found on this network."

The list is only a view. To use one of those computers' channels, go to Setup, Channels, From another Earshot host.

Finding other Earshot computers needs Bonjour (mDNS) to work on your network. If the network blocks it, Earshot finds nothing. Type the address instead.

Finding each other between two computers has not been tried

Two Earshot hosts have been run and linked on one Mac. Discovery between two separate machines on a real network has not been tried. See Limits and known behaviour.

Which addresses Earshot answers to​

Earshot checks the address a browser used before it answers anything. It answers to:

  • Any IP address of the computer, for example http://192.168.1.20:4780/.
  • localhost, on the host computer itself.
  • The computer's own name, with or without .local.
  • The name it announces on the network.
  • Any extra name you allowed when starting it (below).

Anything else gets the "Wrong address" card: "This address isn't one the host recognises. Use the address shown on the operator's screen."

This is a safety check, not a fault. It stops a web page elsewhere from quietly pointing a made-up name at the Earshot computer and talking to it through someone's browser.

Allowing a name of your own​

If crew must reach Earshot through a name you control, such as a venue DNS name or the name of a reverse proxy, tell Earshot the name when you start the headless program:

earshotd --allow-host earshot.venue.example

Repeat the flag for more names:

earshotd --allow-host earshot.venue.example --allow-host comms.venue.example

Give the bare name: no http://, no port, no path. See earshotd for every option.

There is no screen for this, and the desktop app has no such setting in this build.

If you put something in front of Earshot​

Two things follow from how Earshot works, and neither has been tried on a real network:

  • Everyone behind a proxy looks like one device. Earshot counts wrong password tries by the address a connection comes from. Behind a reverse proxy that is the proxy's address for everybody, so one person's five wrong tries lock out new sign-ins for all of them for a while. People already signed in carry on. See The shared password.
  • Do not count on a proxy to give Earshot https in this build. Earshot expects a browser to be talking to it at the same scheme, name and port that it is serving. If a proxy offers https:// to browsers and passes plain http on to Earshot, Earshot sees commands from those browsers as coming from another site and refuses them.

Choosing the network interface and the port​

WhatHow
The web port4780 by default. earshotd --port 4790 chooses another. The desktop app uses 4780, and if that port is busy it starts on another and tells you which in a dialog.
Which network interface to listen onAll of them by default. earshotd --bind 192.168.1.20 listens on one address only.
Listening on the host computer onlyearshotd --bind 127.0.0.1. Nobody else can connect, Address for the crew is empty, and Earshot does not announce itself.

There is no Setup screen for the interface or the port in this build. They can only be set when starting earshotd.

Example: a rack machine with a show network card at 10.0.1.5 and a management card you do not want Earshot on:

earshotd --bind 10.0.1.5 --port 4780

OSC input listens on the same address as the web app. See OSC input.

No https for Earshot's own address​

Earshot serves plain http in this build. There is no setting to give it a certificate.

What that means for you:

  • Anyone who can listen on the network can read the transcript, passwords as they are typed, and personal links as they are opened. Keep Earshot on a network only the crew can join.
  • Most phones and browsers will not install Earshot as an app from a plain http address. It works the same in the browser. See Earshot on a phone.
  • Links between Earshot computers offer "Encrypted (https)", but that has not been proven end to end. Treat links as not encrypted.

Example: two Earshot computers in one venue​

The stage rack and the broadcast truck each run Earshot.

  1. On each, open Setup, Access, Network and set Name shown to others: Main stage and Broadcast truck. Press Save name.
  2. Leave Announce on the network (Bonjour) on, on both.
  3. On the truck, press Look again. If Main stage appears with its address, the two can see each other. If not, the network is probably blocking Bonjour: note the stage rack's address from its Address for the crew and type it when linking.
  4. Carry on with Showing another Earshot computer's channels.
