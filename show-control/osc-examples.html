OSC examples

Worked examples of the messages in the address list. Read OSC input first: nothing here works until OSC input is switched on, and most of it needs the level Trigger automations and the sending device on the allowed list.

What has been tried

The Python examples on this page that use only Python's own library were run against a demo host on the same computer (over 127.0.0.1), and the results shown are what came back. The oscsend and python-osc lines send the same messages but were not run for this manual. Nothing here has been tried against a real console, or between two computers on a real network. Try your own gear in rehearsal. See Limits and known behaviour.

The examples use these values. Change them to yours.

ValueIn the examplesWhere to find yours
The host's address192.168.1.20Setup, Access, Address for the crew
UDP port4781Setup, Show control, UDP port
TCP port4782Setup, Show control, TCP port (optional). Empty until you set one.
A channelShow Caller, short name show-caller, first in the listSetup, Channels
An automationGo cue, short name go-cueAutomations

Three ways to send​

From the command line: oscsend​

oscsend comes with liblo (on a Mac with Homebrew, brew install liblo). Its form is: host, port, address, then the argument types and the arguments.

oscsend 192.168.1.20 4781 /earshot/armed/off

The type letters are s for a string, i for a whole number, f for a decimal number, and T and F for true and false (which take no value). oscsend only sends. It cannot show a reply.

From Python, with python-osc​

from pythonosc.udp_client import SimpleUDPClient

earshot = SimpleUDPClient("192.168.1.20", 4781)
earshot.send_message("/earshot/armed/off", [])

From Python, with nothing installed​

An OSC message is small enough to build by hand. This helper is used in the rest of the page. It needs only Python 3.

import socket
import struct


def pad(data: bytes) -> bytes:
    """OSC strings end with a zero byte and are padded to a multiple of four."""
    return data + b"\0" * (4 - len(data) % 4)


def osc(address: str, *args) -> bytes:
    """Build one OSC message. Arguments may be str, int, float, True or False."""
    tags, data = ",", b""
    for arg in args:
        if arg is True:
            tags += "T"
        elif arg is False:
            tags += "F"
        elif isinstance(arg, int):
            tags += "i"
            data += struct.pack(">i", arg)
        elif isinstance(arg, float):
            tags += "f"
            data += struct.pack(">f", arg)
        else:
            tags += "s"
            data += pad(str(arg).encode())
    return pad(address.encode()) + pad(tags.encode()) + data


EARSHOT = ("192.168.1.20", 4781)
udp = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

udp.sendto(osc("/earshot/armed/off"), EARSHOT)

Make the show Safe​

This works from any device, at every level, over UDP or TCP. It is the one message worth putting on a button on every desk.

oscsend 192.168.1.20 4781 /earshot/armed/off

The other spelling takes one argument: false, the number 0, or the string "off".

oscsend 192.168.1.20 4781 /earshot/armed F
oscsend 192.168.1.20 4781 /earshot/armed i 0
oscsend 192.168.1.20 4781 /earshot/armed s off
udp.sendto(osc("/earshot/armed/off"), EARSHOT)
udp.sendto(osc("/earshot/armed", False), EARSHOT)

There is no reply. Look at the header of any Earshot screen: it shows Safe.

tip

Send Safe as a small message on its own, not inside a large bundle. See "Safe always wins" in OSC input.

Check the connection: ping and version​

/earshot/ping comes back as /earshot/reply/pong with the arguments you sent. /earshot/version comes back as /earshot/reply/version with the app version. Both work from any device at every level, so they are the way to prove that the address, the port and the network are right before you try anything else.

The reply goes to the address and port the message came from, so listen on the same socket you sent from:

udp.settimeout(2)

udp.sendto(osc("/earshot/ping", 7, "hello"), EARSHOT)
print(udp.recvfrom(4096)[0])

udp.sendto(osc("/earshot/version"), EARSHOT)
print(udp.recvfrom(4096)[0])

What came back from the demo host:

b'/earshot/reply/pong\x00,is\x00\x00\x00\x00\x07hello\x00\x00\x00'
b'/earshot/reply/version\x00\x00,s\x00\x000.1.0\x00\x00\x00'

That is /earshot/reply/pong 7 "hello" and /earshot/reply/version "0.1.0". If nothing comes back within two seconds, OSC input is off, the port is wrong, or something between the two computers is blocking UDP.

Select a channel on the host's screen​

Needs the level Trigger automations. This changes the Earshot window on the host computer only. It is never sent to phones or other computers, and it does nothing while someone on the host is in Setup, Automations, Archive or Activity.

By name, as an argument:

oscsend 192.168.1.20 4781 /earshot/channel/select s "Show Caller"

By short name, in the address:

oscsend 192.168.1.20 4781 /earshot/channel/show-caller/select

By position (1 is the first channel), in the address or as an argument:

oscsend 192.168.1.20 4781 /earshot/channel/1/select
oscsend 192.168.1.20 4781 /earshot/channel/select i 1

Step through the channels, and get back to the newest line:

oscsend 192.168.1.20 4781 /earshot/channel/next
oscsend 192.168.1.20 4781 /earshot/channel/previous
oscsend 192.168.1.20 4781 /earshot/scroll/live

Send a typed line into a channel​

Needs Trigger automations. The line appears in that channel with a Typed badge, as if someone had typed it in the Feed.

oscsend 192.168.1.20 4781 /earshot/channel/show-caller/send s "Front of house is clear"
oscsend 192.168.1.20 4781 /earshot/channel/send ss "Show Caller" "Front of house is clear"
udp.sendto(osc("/earshot/channel/show-caller/send", "Front of house is clear"), EARSHOT)
udp.sendto(osc("/earshot/channel/send", "Show Caller", "Front of house is clear"), EARSHOT)

A typed line never fires a phrase automation, so a console cannot use this to "say" a cue. To fire an automation from a console, see "Run an automation" below.

Flash an alert on every screen​

Needs Trigger automations. The first argument is the text. The second, if you send one, is a colour. The third, if you send one, makes the alert stay until an operator presses Acknowledge.

oscsend 192.168.1.20 4781 /earshot/flash s "Five minutes"
oscsend 192.168.1.20 4781 /earshot/flash ss "HOLD" "#ff4639"
oscsend 192.168.1.20 4781 /earshot/flash ssT "HOLD" "#ff4639"
udp.sendto(osc("/earshot/flash", "Five minutes"), EARSHOT)
udp.sendto(osc("/earshot/flash", "HOLD", "#ff4639", True), EARSHOT)

The last one stays on every screen until someone acknowledges it. The until-ack argument can be true or false, or the numbers 1 or 0.

Add a marker​

Needs Trigger automations. The marker goes into the current session at this moment. The label is optional.

oscsend 192.168.1.20 4781 /earshot/marker/add s "Act two"
oscsend 192.168.1.20 4781 /earshot/marker/add

Find it afterwards in the Archive, in the session's marker list.

Do not confuse this with /earshot/channel/mark, which means mark read: it clears the unread counts on the host's screen.

Run an automation​

Needs Trigger automations. This is the same as pressing Run now. While the show is Safe it is a dry run: Activity shows what would have been sent, and nothing is sent.

By short name, in the address:

oscsend 192.168.1.20 4781 /earshot/automation/go-cue/trigger

By name, short name or id, as an argument:

oscsend 192.168.1.20 4781 /earshot/automation/trigger s "Go cue"
udp.sendto(osc("/earshot/automation/go-cue/trigger"), EARSHOT)

Things to know:

  • A manual run carries no spoken words, so a value such as {{capture.number}} is empty. An automation that puts a spoken number into an OSC address has nothing to put there when you run it this way. Use an OSC-triggered automation instead (next section) if the console needs to pass a value.
  • Press it twice less than 0.1 seconds apart and the second is refused.
  • An automation started by OSC that fires more than 20 times in 10 seconds is stopped. See OSC input.

Fire an automation with a value from the console​

An automation whose trigger is An incoming OSC message listens for an address of your own choosing, outside /earshot/. Put a name in braces where a value goes.

  1. In the automation editor, under When, choose An incoming OSC message and give it the pattern /cue/{n}/go.
  2. Give it an action that uses the value, for example Add a marker with the label Cue {{capture.n}} called from the desk.
  3. From the console, send:
oscsend 192.168.1.20 4781 /cue/7/go

The automation fires with {{capture.n}} set to 7. The arguments of the message are available too, as {{osc.args.0}}, {{osc.args.1}} and so on, and the whole address as {{osc.address}}. See Triggers and Variables.

This needs the level Trigger automations and the console on the allowed list. Like every automation, it sends nothing unless the show is Armed.

List the automations​

Needs Trigger automations. The reply is /earshot/reply/automation/list with one string per automation: its short name.

udp.sendto(osc("/earshot/automation/list"), EARSHOT)
print(udp.recvfrom(4096)[0])

From the demo host, which has one automation:

b'/earshot/reply/automation/list\x00\x00,s\x00\x00standby-marker\x00\x00'

What a refusal looks like​

A device that is allowed to control gets an error back when a message cannot be carried out. It is /earshot/error with two strings: the address you sent, and the reason.

udp.sendto(osc("/earshot/nonsense"), EARSHOT)
print(udp.recvfrom(4096)[0])
b'/earshot/error\x00\x00,ss\x00/earshot/nonsense\x00\x00\x00unknown Earshot OSC command\x00'

A device that is not allowed to control gets no error back. Look in Activity on the host instead: refused OSC is logged there with the sender's address and the reason, for example "OSC from 10.0.0.9 refused: this source is not allowed to trigger".

Arm the show over TCP​

danger

Arming lets automations really send cues. Read Safe and Armed first. Most shows should arm from the screen, by hand, and use OSC only to make Safe.

Arming by OSC needs all of these: the level Full control, including arming, a TCP port set and saved, the sending device on the allowed list (or it is the host itself), and a TCP connection. Sent over UDP, /earshot/armed/on does nothing, and Activity says "Arming by OSC needs the TCP port".

Earshot's TCP port speaks OSC 1.1: each message is wrapped in SLIP framing. That means a byte 0xC0 before and after each message, with any 0xC0 inside the message written as 0xDB 0xDC and any 0xDB as 0xDB 0xDD. Many consoles and OSC libraries offer this as "TCP (SLIP)" or "OSC 1.1". The older style, where each message starts with its length, is not accepted.

With the osc() helper from the top of the page:

import socket

END, ESC = b"\xc0", b"\xdb"


def slip(message: bytes) -> bytes:
    """Wrap one OSC message in SLIP framing (OSC 1.1 over TCP)."""
    return END + message.replace(ESC, b"\xdb\xdd").replace(END, b"\xdb\xdc") + END


tcp = socket.create_connection(("192.168.1.20", 4782))

tcp.sendall(slip(osc("/earshot/armed/on")))      # arms
# ... the show runs ...
tcp.sendall(slip(osc("/earshot/armed/off")))     # makes Safe
tcp.close()

Run against the demo host on the same computer, with the level at Full control: /earshot/armed/on over UDP left the show Safe; the same message over TCP armed it; /earshot/armed/off made it Safe again. /earshot/armed with true over TCP arms as well.

Replies come back over the same connection, framed the same way. A ping sent over TCP came back as:

b'\xc0/earshot/reply/pong\x00,i\x00\x00\x00\x00\x00\x01\xc0'

Things to know about the TCP connection:

  • It must begin with an OSC message. Anything else closes it at once.
  • One bad frame closes it.
  • It is closed after 60 seconds with nothing sent. Send /earshot/ping every so often to keep it open, or open a new connection each time.

Arm and Safe: the order matters​

Arm and Safe are applied in the order they arrive, and the last one wins.

You sendThe show ends
Arm, then Safe, as two packets (or two TCP frames)Safe
Safe, then Arm, as two packets over TCPArmed
Arm and Safe in one bundle, in either orderSafe. The Arm is ignored: "Arm ignored: the same OSC packet also made the show Safe".
Safe by UDP while an Arm is still on its way by TCPWhichever the host receives last wins.

If you mean both, send them as separate packets. If you mean "definitely Safe", send Safe on its own, and send it again if you are unsure: making Safe is never rate-limited.

Setting up a console​

Every console words this differently, so these are the things to enter, not the menus to find them in.

A playback machine sending a network cue (for example QLab)​

EnterValue
Destination addressThe host's address, for example 192.168.1.20
Destination portThe UDP port from Show control (4781 unless you changed it)
TypeOSC message, UDP
Message, to make Safe/earshot/armed/off with no arguments
Message, to add a marker/earshot/marker/add with one string argument, for example Act two
Message, to run an automation/earshot/automation/go-cue/trigger with no arguments

On Earshot: OSC input on, the level at Trigger automations (for the marker and the automation), and the playback machine's IP address under Devices allowed to control.

A lighting desk macro or OSC output​

EnterValue
OSC output address (the "TX" address)The host's address
OSC output port (the "TX" port)The UDP port from Show control
The string or command the macro sends/earshot/armed/off, or your own plain address such as /cue/7/go

Many desks add their own prefix to every address they send, or send their own messages on every cue. Look at Activity on the Earshot host while you press the button on the desk. Every message Earshot lets through is logged there as "OSC in", with its address, its arguments and where it came from, so you can see exactly what the desk sent and match your automation's pattern to it. A message that was refused is logged with the reason.

Sending cues the other way​

To have Earshot send a cue to the desk when it hears a phrase, you do not need OSC input at all. Add the desk as an OSC destination and use a Send OSC action. See Actions and Recipes.

If it does not work​

  1. Send /earshot/ping and wait for the pong. No pong means the message is not reaching Earshot: check that OSC input is on, the port, the network, and any firewall on the host.
  2. A pong but nothing else works: check the level, and that the sending device's IP address is on the allowed list.
  3. Look in Activity on the host. Refused OSC is logged with the reason.
  4. Check the spelling against the address list. There are no aliases.

The full list is in Troubleshooting.
