MIDI

Earshot uses MIDI in two ways. A MIDI message coming in can trigger an automation: a pad, a key, a fader or a program change. An automation can send a MIDI message out as one of its actions.

warning

MIDI has been tried only in automated tests against stand-ins on one Mac. It has never been tried against real gear. See Limits and known behaviour.

Choose the MIDI inputs to listen to​

Open Setup, then Show control. Only admins can. Under MIDI inputs the screen says "Earshot listens to the ports you tick. MIDI messages from them can trigger automations."

  1. Tick each port you want Earshot to listen to.
  2. If you plugged a controller in after Earshot started, press Refresh.
  • No port is ticked to begin with, so no MIDI message is listened to.
  • If no ports are found, the screen says "No MIDI inputs found. Plug in or switch on a controller, then choose Refresh."
  • A port you ticked that is not plugged in right now stays in the list with the badge Not connected.
  • The ticked ports are a setting of this computer. An imported show file does not change them. See Show files.

MIDI has no levels and no allowed-device list, unlike OSC input. Whatever arrives on a ticked port can trigger the automations that listen for it. MIDI cannot arm the show, cannot make it Safe and cannot run Earshot's own controls: it only triggers automations.

Fire an automation from MIDI​

A new MIDI trigger in the mock show's editor. Not a real show.

In the automation editor, under When, choose An incoming MIDI message. See Building an automation for the rest of the editor.

Example: a pad that flashes "STANDBY"​

  1. Tick the pad controller's port under Setup, Show control, MIDI inputs.
  2. Automations, New automation. Name it "Standby pad".
  3. When: An incoming MIDI message. Message: Note on. Note: 60. Leave the port and channel on Any.
  4. Then: add Flash an alert with the text STANDBY.
  5. Save. While the show is Safe, press the pad and look in Activity: the row says Would have fired Standby pad with Dry run.

Every MIDI message that arrives on a ticked port is logged in Activity as "MIDI in", so you can press the pad first and read off its note and channel.

What a MIDI trigger cannot do​

  • An automation limited to named people never fires from MIDI, because no voice was heard. Activity says "no voice was heard for this trigger". See Automations limited to people.
  • Like every automation, it sends nothing unless the show is Armed.

Send MIDI from an automation​

Add the action Send MIDI under Then. See Actions.

MIDI channel (1 to 16)For every message except Raw bytes.

Raw bytes (hex)"Like 90 3C 7F: status byte, then data bytes." Only hex digits, separated by spaces. The first byte must be a status byte.

The note, velocity, controller, value and program boxes accept a variable, so a spoken number can become a program change: with the phrase preset {n}, set Program to {{capture.n}}. The result must be a whole number from 0 to 127. If it is not, that message is not sent, and Activity says why.

A MIDI send is on time or it does not go​

If the MIDI port is busy for more than 1 second, the send is dropped. Activity says "not sent: the MIDI port was busy for more than 1 s". It is never sent late and reported as sent. A MIDI cue is on time or it does not go.

What Safe does to MIDI​

Pressing Make safe stops a MIDI message even while its port is still opening. The message is checked again right before it goes to the driver.

Safe cannot recall a MIDI message already handed to the driver. See Safe and Armed.

MIDI feedback loops​

A feedback loop is an automation whose MIDI output comes back in as its own trigger: for example, it sends note 60 to a port that is also a ticked input, and it is triggered by note 60.

  • The runaway stop (20 firings in 10 seconds) applies to automations started by OSC or a web request. MIDI is exempt from it.
  • A MIDI loop is limited only by the rule that any two firings of one automation from anything other than speech are at least 0.1 seconds apart. That is about ten firings a second.
  • It carries on until you make the show Safe.

To avoid one: do not tick, as an input, a port that an automation sends to. If you must, give the automation a Cooldown long enough to break the loop, and trigger on a different note from the one it sends.

If MIDI is not triggering​

  1. Is the port ticked under Setup, Show control, MIDI inputs? Press Refresh if the controller was plugged in late.
  2. Does Activity show "MIDI in" rows when you press the control? If not, the message is not reaching Earshot.
  3. Do the message type, channel and number in the automation match what Activity shows?
  4. Is there a Minimum velocity or Minimum value the control is not reaching?
  5. Is the show Armed? In Safe, Activity shows the row as a Dry run.
  6. Is the automation on, with no Problem badge? See When an automation is not running.
