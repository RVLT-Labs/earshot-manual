Consoles and controllers

Earshot talks to other show gear in both directions. Messages come in from a console, a controller or a script, and can trigger automations or operate Earshot. Messages go out from automations to lighting desks, playback machines and web services.

Everything that comes in is set on one screen: open Setup, then Show control. The page says "Decide how lighting desks, controllers and other devices may drive Earshot, and what Earshot does when it starts."

Who can do this

Only admins can open Setup. Operators and viewers see "Setup needs admin access". See Roles.

The Show control screen in the mock show. It is not a real show. The mock show uses UDP port 53000; a new show uses 4781.

What goes in and what comes out​

Nothing on the right-hand side happens while the show is Safe. In Safe, an automation that matches is logged as "would have fired" and nothing is sent. See Safe and Armed.

Start armed​

Start armed makes automations able to fire as soon as Earshot starts. The switch says "Automations can fire as soon as Earshot starts. Leave this off unless the show runs unattended."

Turning it on asks "Start Armed?" and says: "Automations can fire as soon as Earshot starts, before anyone has looked at the show. Leave this off unless the show runs unattended."

danger

With Start armed on, a restart of the host brings the show back Armed. Without it, a restart always comes back Safe. See What happens when the host restarts.

An imported show file never changes this switch. It is a setting of this computer, not of the show. See Show files.

Allow automations to run shell commands​

An automation can run a shell command on the host computer. This is off until an admin turns on Allow automations to run shell commands. The switch says "Automations will be able to run programs on this computer with your user account's rights."

Turning it on asks "Allow shell commands?" and says: "Automations will be able to run programs on this computer with the rights of the account Earshot runs as. Shell automations that were refused until now will start working, and run for real when the show is Armed." Press Allow shell commands to confirm.

  • A shell command runs on the host, with the rights of the account Earshot runs as.
  • It runs for real only while the show is Armed.
  • Pressing Make safe stops a running shell command, together with the programs it started. (Stopping the child programs is untested on Windows.)
  • Importing a show file never turns this switch on, and every automation with a shell action arrives switched off. Read what each one does, then switch it on yourself.

See Actions for how a shell action is written.

The API reference​

At the top right of Show control, API reference opens /docs on the host in a new tab. It lists every web address Earshot answers, with an example for each, a walk-through of the live connection, and the OSC address list. It asks you to sign in to Earshot in that browser first, unless the show is Open.

See HTTP API.

What has been tried​

warning

No real console has been connected to Earshot. MIDI, web requests and TCP OSC against real gear have been tried only in automated tests against stand-ins on one Mac. Try your own desk in rehearsal before you rely on any of this. See Limits and known behaviour.
