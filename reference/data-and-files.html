Data and files

Earshot keeps everything on the host computer, in one folder: the data folder. Nothing is kept on the crew's phones and laptops except their own display choices and their sign-in.

Where the data folder is​

SystemFolder
macOS~/Library/Application Support/Earshot
Windows and LinuxThe operating system's data folder, in a folder called Earshot. (Not tested on those systems.)

To put it somewhere else:

  • for the desktop app or earshotd, set the environment variable EARSHOT_DATA_DIR before starting;
  • for earshotd you can pass --data-dir instead.
EARSHOT_DATA_DIR=/Volumes/Show/earshot earshotd
earshotd --data-dir /Volumes/Show/earshot

earshotd writes the folder it is using to its log when it starts ("data directory: …"). See earshotd.

Demo mode

In demo mode (earshotd --demo, or the desktop app with EARSHOT_DEMO=1), the data folder is not read or written at all. Nothing you do in a demo is kept.

What is in it​

Earshot/
├── earshot.db              transcripts, markers, personal links
├── earshot.db-wal          (beside the database while Earshot runs)
├── earshot.db-shm          (beside the database while Earshot runs)
├── show.earshot.json       the show, and this computer's settings
├── show.earshot.json.bak   the show as it was before the last save
├── models/                 downloaded speech and translation models
└── clips/                  saved audio, one file per line
PathWhat it holds
earshot.dbThe transcripts of every session, markers, and personal link records, in one SQLite database. For a line changed by the glossary or by number tidying, it holds both the changed text and what was heard. The files beside it whose names start earshot.db belong to it.
show.earshot.jsonThe show: channels, groups, automations, OSC destinations, glossary, people. And this computer's settings: who can connect, OSC and MIDI input, cloud options, saved-audio limits. The password is stored as a hash. Cloud keys and the link codes of linked channels are stored here. People's learned voices are stored here as well.
show.earshot.json.bakThe show file as it was before the most recent save. Each save writes a new file, then swaps it in, and keeps the previous one as this backup.
models/The downloaded speech and translation models, one folder per model. Set EARSHOT_MODELS, or pass --models-dir to earshotd, to keep them somewhere else.
clips/Saved audio, for channels with Keep audio for replay on: one WAV file per spoken line.

How big it gets​

WhatSize
Silero VADAbout 0.6 MB
Parakeet TDT 0.6b v3About 487 MB
Voice recognition (CAM++)About 29 MB
Each translation pairAbout 80 to 240 MB
Saved audioUp to the limit under Setup, Cloud & audio, At most (MB). It starts at 2048 MB, and clips are kept for 14 days. 0 means no limit.
TranscriptsText only. Small beside everything else.

See Models and Replay a line's audio.

The show file in the folder is not the show file you export​

There are two things called a show file. They are not the same.

show.earshot.json in the data folderThe file from Export show file
What it is forEarshot's own working copyCarrying a show to another computer
The password, cloud keys, link codesStored in itNot in it
Learned voicesStored in itNot in it
Webhook addresses, HTTP header values, shell commandsStored in itHidden
This computer's settings (access, OSC and MIDI input, Start armed)Stored in itIgnored when imported

danger

Never hand someone the show.earshot.json from the data folder. It holds your cloud keys, link codes and the crew's learned voices. To share a show, use Setup, Show file, Export show file. See Show files.

Do not edit show.earshot.json by hand. Earshot writes the whole file on every save, so a change made while it runs would be lost. And if the file is there but cannot be read, Earshot does not start with an empty show in its place: it reports the error and does not start.

Who can read the folder​

  • The folder is private to your user account. A folder Earshot creates can be opened only by you, and the show file, its backup and the database are readable only by you.
  • That holds on macOS and Linux. A folder that already existed keeps the permissions it had; the files inside are still made private.
  • Other user accounts on the same computer, and anyone with administrator rights, are a matter for the computer, not for Earshot.

See Privacy for who can read the transcript through the app.

Backing up​

Everything worth keeping is in the data folder. To back up a show completely:

  1. Stop Earshot. The database is being written while it runs, and a copy taken mid-write may not open.
  2. Copy the whole data folder somewhere safe.
  3. Start Earshot again.

You can leave models/ out of the copy: models can be downloaded again (with internet). Everything else cannot be made again.

warning

A copy of the data folder contains your cloud keys, link codes, the password hash, every transcript and the crew's learned voices. Keep it as carefully as the host itself.

Two lighter copies you can take while Earshot runs, from the screens:

WhatWhereWhat you get
The showSetup, Show file, Export show fileChannels, groups, automations, destinations, glossary, people's names. No secrets, no voices, no transcript.
One session's transcriptArchive, ExportTXT, CSV, JSON or SRT. See Archive and search.

Moving to another computer​

  1. On the old computer: Setup, Show file, Export show file.
  2. On the new one: install Earshot, download the models, then Setup, Show file, Choose a show file….
  3. Then, on the new computer, do again by hand everything an export leaves out:
    • who can connect, and the password (Setup, Access);
    • cloud keys (Setup, Cloud & audio);
    • OSC and MIDI input (Setup, Show control);
    • link codes of linked channels;
    • webhook addresses, HTTP header values and web addresses in automations, which arrive empty and switched off;
    • every learned voice. Voices are never exported.

See Show files for exactly what an import brings and what it leaves alone.

Copying the whole data folder to the new computer instead brings everything, secrets and voices included. That has not been tried between two computers.

Starting a fresh history​

There is no button for deleting past sessions in this build.

  1. Stop Earshot.
  2. In the data folder, delete earshot.db and the files beside it whose names start earshot.db.
  3. Delete the clips folder.
  4. Start Earshot again.

This also removes the personal links, so everyone who joined with a link or an invite needs a new one. It does not touch the show: channels, automations, the glossary, people and settings stay.

To start completely clean, delete the whole data folder with Earshot stopped. The next start makes a new one, with an empty show, and the first-time setup opens. You will need to download the models again unless you kept models/.

For a clean transcript without deleting anything, use Setup, Show file, New session…. The old session stays in the Archive.

If the show file is damaged​

Earshot treats the two cases differently:

  • The file is missing. Earshot starts with a new, empty show.
  • The file is there but cannot be read (it is damaged, or was written by a build with a different show version). Earshot does not start, and its log names the file and says what is wrong. It never quietly replaces your show with an empty one.

The copy from before the last save is beside it as show.earshot.json.bak. With Earshot stopped, move the damaged file somewhere else, copy the .bak file to show.earshot.json, and start Earshot. You lose only the most recent change. Earshot does not do this for you, and this recovery has not been rehearsed for this manual: keep your own exported show file as well.

What is kept in the browser​

Each phone, tablet and laptop keeps a little of its own, in the browser it used:

  • display choices: theme, text size, the language under Read in, which channels and lanes are shown;
  • its sign-in (a personal link's token, or a password session).

None of that is on the host, and clearing the browser's site data removes it. A person who clears it needs their link or the password again.
