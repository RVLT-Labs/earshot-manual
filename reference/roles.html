Roles

Everyone connected to Earshot has one of three roles: viewer, operator or admin. The role decides what they can do. It does not decide what they can read: any role can read the transcript.

The host enforces roles on every request. The screens only reflect what the host allows, so hiding a button is never the only thing standing between a viewer and arming the show.

An operator who opens Setup sees "Setup needs admin access".

danger

An operator can arm the show and fire cues. When you hand out operator access, by invite, personal link, the shared password or Open mode, you are handing out the Armed control.

How a sign-in becomes a role​

It depends on the access mode (Setup, Access, Who can connect) and on how the person got in.

Three things in that table surprise people:

  • Earshot starts in Open mode, and in Open mode everyone on the network is an operator. That includes the ability to arm. Change the mode before you put Earshot on a network you do not control. See Who can connect.
  • In Open mode a viewer link is raised to operator. There are no viewers in an Open show. If you need real viewers (people who can read but not arm, and who are not sent what was heard), use Personal links, or Password with viewer links.
  • The shared password always makes an operator. There is no viewer password.

The Access screen makes invites and personal links for two roles only: Viewer ("can read, and type where a channel allows it") and Operator ("can arm the show, run automations and add markers"). Admin access stays with the host's own window and the Admin: address. (The API can make a link with the admin role. Such a link is listed as "Can change everything, including Setup".)

The admin address​

earshotd prints an Admin: address with a token on the end when it starts. Whoever opens it is an admin, in every access mode. The token is new each time the program starts, unless you set one with --admin-token. Treat it like the keys to the building. See earshotd.

Names are labels, not identities​

The name beside a typed line is whatever that person typed when they joined, or the label on their personal link. Earshot does not check it. The role comes from the link or password, never from the name.

Changing or removing access​

  • Revoke next to a person (Setup, Access, People with access) cuts off that one link. They are disconnected within a second.
  • Changing or clearing the show password signs out everyone who used it.
  • Changing the access mode applies at once, to everyone, and asks you to confirm first.
  • If a person's role changes while they are connected, their screen reconnects and picks up the new role.

See Invites and personal links and The show password.

What no role is ever sent​

Some things never leave the host, whoever asks.

Never sent toWhat
Anyone, admins includedA saved cloud key, a saved link code, the show password (it is stored as a hash), an automation's web-request header values, and a webhook's path. Where one is saved an admin sees "••••", and can keep it, clear it or replace it, but never read it back.
Anyone, admins includedLearned voices. They stay on the host, are never sent to any browser, and are never in an exported show file.
Anyone, admins includedA show file export always has secrets hidden, even when an admin exports it.
Operators and viewersWeb addresses in automations are cut back to the host name, and request bodies and shell command text are hidden. Admins see those, because they need to edit them.
Operators and viewersWebhook paths in the Activity log and in alerts. They show as plain "webhook".

Because everyone in an Open show is an operator, everyone in an Open show can see what was heard. See Privacy and Saved secrets.

What OSC can do is separate​

A console sending OSC has no sign-in and no role. What it may do is decided by where the message came from and the level chosen under Setup, Show control: Make safe only, Trigger automations, or Full control, including arming. See OSC input.

Similarly, anyone who has a webhook's address can fire that one automation, in any access mode, though it still obeys Armed and Safe. See Triggers.

A worked example: a touring show​

The mock show plays a venue whose network the production does not control.

  • The stage manager runs the host from the desktop app's window: admin.
  • Access is set to Personal links.
  • The deputy stage manager and the lighting programmer each get a personal link made as Operator, because either may need to press Make safe.
  • Dressers, follow-spot operators and the company manager scan an invite made as Viewer. They can read, type notes into channels that allow it, and replay calls. They cannot arm, and they see no pencil.
  • The lighting desk sends OSC at the Trigger automations level, with its address in the allowed list. It has no role at all.

When the programmer leaves the tour, the stage manager presses Revoke beside their name. Nobody else is affected.
