Building from source

This page is for developers and people who need a custom build. To install Earshot for use, start with installation and updates. You do not need Rust, Node.js, pnpm or a repository checkout to use a release build.

Get the source​

git clone https://github.com/RVLT-Labs/earshot.git
cd earshot

To reproduce a release, check out its tag before installing dependencies. The commands below run from the repository root unless stated otherwise.

Requirements​

  • Rust 1.98.1. rust-toolchain.toml pins it and asks for rustfmt and clippy. With rustup installed, the first cargo command in the repository installs it.
  • Node.js and pnpm. pnpm-lock.yaml is lockfile version 9. The CI workflow selects Node 24 and pnpm 12; local work has also used Node 26.
  • CMake (3.15 or newer) and a C++17 compiler. The translation crate (earshot-translate) builds CTranslate2 from source. The first build takes a few minutes. On macOS that means the Xcode command-line tools and CMake; on Windows, MSVC; on Linux, gcc or clang. Nothing is downloaded for this step. The C++ SentencePiece library is no longer part of normal builds: the tokenizer is written in Rust, and the C++ one is kept only as a dev-dependency for a test that compares the two. (Linking both SentencePiece and sherpa-onnx into one program made the speech model fail to load, so CI checks that sentencepiece-sys stays out of the program.)
  • Network access at build time. The speech crate's dependency, sherpa-onnx, fetches its prebuilt runtime when it builds. macOS uses Core ML-capable shared libraries, which are included in the desktop app bundle. Other platforms retain the static speech runtime.
  • Linux only: ALSA development headers for audio capture, and the packages Tauri 2 needs for the desktop app. See Tauri's prerequisites. The CI workflow lists the packages it installs. Linux has not been built here.
  • The desktop bundle is built for macOS 11 or newer.

See Apple Silicon performance for model runtime choices and reproducible probes.

Build and run locally​

Install the web dependencies once, from the repository root:

pnpm install --frozen-lockfile

The web app​

pnpm build:web            # builds apps/web/dist

For development, run the Vite server, which proxies /api to a host on 127.0.0.1:4780:

pnpm dev:web

Open the address Vite prints with ?mock=1 on the end (for example http://localhost:5173/?mock=1) to use the built-in mock host and no engine at all. Other mock options are described in apps/web/src/runtime/runtime.ts.

The demo (no models, no audio hardware)​

cargo run -p earshotd -- --demo --bind 127.0.0.1

Then open http://localhost:4780/. It plays a scripted transcript. Your own data is not read or written. earshotd serves apps/web/dist if it exists, so build the web app first.

The real engine, with models​

cargo run -p earshotd --release

To build a headless executable without starting it:

cargo build --locked -p earshotd --release

The executable is target/release/earshotd (earshotd.exe on Windows). It does not embed the web app. Keep a copy of apps/web/dist alongside the executable, for example as a folder named web, and pass its path explicitly when running outside the checkout:

./earshotd --web-dir ./web

It prints an Open: address and an Admin: address. Use the Admin address. In the app, open Setup, then Models, and download the models you need. They are downloaded once and checked against a checksum.

ModelSizeNeeded for
Silero VADabout 0.6 MBFinding speech. Recommended.
Parakeet TDT 0.6b v3about 487 MBSpeech to text. Recommended.
Voice recognition (CAM++)about 29 MBNames on lines (optional). Its checksum was pinned from the first download; no published digest exists.
Whisper smallabout 375 MBExperimental, never run.
Translation pairs (Opus-MT)about 80 to 240 MB eachReading in another language (optional). German to English and English to Spanish have been run.

Then choose inputs under Setup, Patch. The user guide walks through it.

earshotd options (cargo run -p earshotd -- --help): --port (default 4780), --bind (default 0.0.0.0), --data-dir, --models-dir, --web-dir, --admin-token, --allow-host, --demo. IP addresses, localhost and the computer's own name always work as web addresses. Anyone typing another name (a venue DNS name, a reverse proxy) is refused until you add it with --allow-host NAME (repeat the flag for more).

The speech tests that use real models are marked ignored. To fetch the recommended models for them (about 488 MB): EARSHOT_MODELS=$PWD/.models cargo test -p earshot-speech -- --ignored download_recommended.

The desktop app​

Build the web app first (the desktop bundle packs apps/web/dist), then:

pnpm --filter desktop tauri build

The bundle is written to target/release/bundle/ (unless you override Cargo's target directory). The app bundles the built web files as resources and serves them through its local host. A local build is not signed or notarised. To run it in demo mode, set EARSHOT_DEMO=1.

Repository layout​

PathWhat it is
crates/earshot-coreShared types, events, commands and the show-file schema. No I/O.
crates/earshot-audioAudio devices, capture, resampling, level meters, voice detection, the WAV simulator.
crates/earshot-speechSpeech engines (sherpa-onnx), the model manager, text post-processing, the glossary library, voice recognition, a Deepgram cloud client with a local fallback.
crates/earshot-translateLocal translation models (a Rust tokenizer feeding CTranslate2), the optional DeepL and Claude translators, and the translation router.
crates/earshot-automationTriggers, matching, number safety, conditions, actions, the Safe gate.
crates/earshot-ioOSC (UDP and TCP), MIDI and outbound HTTP.
crates/earshot-storeSQLite history, search, export, the show file, tokens, clip storage.
crates/earshot-serverThe HTTP, WebSocket and SSE API, access control, QR invites, Bonjour, the API reference page, and the web app files.
crates/earshot-engineWires the crates together: state, the audio-to-speech pipeline, the glossary, voice recognition, saved audio, translation, cloud speech, links to other hosts, the automation host, OSC input, demo mode.
apps/desktopThe Tauri 2 desktop app (src-tauri).
apps/headlessearshotd, the engine and server with no window.
apps/webThe React and TypeScript web app. It is the only UI.
docs/user-guide.md, api-contract.md (HTTP and WebSocket), osc.md (OSC addresses), screenshots/, and superpowers/specs/ (the design spec).
fixtures/audioSynthetic speech recordings used by the simulator, tests and demos.

Tests​

Run tests for one crate at a time while you work:

cargo test -p earshot-core
cargo test -p earshot-audio
cargo test -p earshot-speech
cargo test -p earshot-translate
cargo test -p earshot-automation
cargo test -p earshot-io
cargo test -p earshot-store
cargo test -p earshot-server
cargo test -p earshot-engine
cargo test -p earshotd
cargo test -p earshot-desktop
cargo clippy -p earshot-engine --all-targets -- -D warnings    # swap in any crate
cargo fmt -p earshot-engine --check

Or everything: cargo test --workspace. Tests marked #[ignore] need downloaded models (set EARSHOT_MODELS) and are run with -- --ignored.

Web app:

pnpm -C apps/web test
pnpm -C apps/web lint
pnpm -C apps/web build

The TypeScript types in apps/web/src/api/types/ are generated from the Rust types. Do not edit them. Regenerate with pnpm types.

CI builds​

The Build workflow tests the web app and Rust workspace. Starting it manually also builds unsigned desktop bundles and uploads them as workflow artifacts. These artifacts are temporary CI outputs; the workflow does not publish GitHub Releases or headless packages. Check the workflow run for its actual platform results. Local release builds for Windows and Linux have passed a headless demo startup smoke test. Their installer interfaces and desktop windows have not been tested.

Browser-only mock show​

The web app has a mock host built in. It needs only Node.js and pnpm, and it runs entirely in your browser.

pnpm install
pnpm dev:web

Open the address it prints with ?mock=1 on the end, for example http://localhost:5173/?mock=1.

The mock plays a different made-up show, "Spring Tour at Harbour Hall". It is the one in this manual's pictures. It already has six sample automations, four people with voices, a glossary and two OSC destinations, so you can look at every screen. It is a stand-in for the engine, not the engine: its model list, its translations and its matching are simplified. Use the demo above when you want to see how Earshot really behaves.

A few extras for looking around, added to the address after ?mock=1:

AddWhat you get
&fresh=1An empty show, so the first-time setup opens.
&role=viewer or &role=operatorThe screens as a viewer or an operator sees them.
&access=passwordA host that asks for a password. The mock's password is show-time-1.
&access=tokensA host that asks for a personal link or code.
&linked=1Three channels linked from other hosts: one working, one refused, one unreachable.
&problems=1One automation reported as not running.
