earshotd, the headless program

earshotd is Earshot with no window: the same engine and the same web screens as the desktop app, for a rack machine with no monitor. You run it from a terminal, and everyone, including you, opens it in a browser.

For packages and installation, see Install and update. For a custom build, see Building from source.

Starting it​

From the extracted package folder, with its web files in web:

./earshotd --web-dir ./web

On Windows, use .\earshotd.exe --web-dir .\web in PowerShell. The examples below use earshotd for the installed executable; use its path if it is not on your PATH.

It prints this, then keeps running:

  Earshot is running
  Open:   http://localhost:4780/
  Admin:  http://localhost:4780/?token=3f9a1c0e5b7d42a68c1e0f2a9b4d6c7e
  Other devices on the network can use this machine's address on port 4780.
LineMeaning
Earshot is runningIn demo mode it says Earshot is running (demo mode).
Open:The plain address. Whoever opens it gets whatever the access mode gives them: an operator while the show is Open. Setup shows "Setup needs admin access".
Admin:The same address with the admin token on the end. Use this one for setup. Whoever opens it is an admin, in every access mode.
Other devices…Printed when it listens on every network address (the default). Give crew the address shown in the app under Setup, Access, Address for the crew, not localhost.
Treat the Admin address like a password

Anyone who has the Admin: address can change everything, including who can connect. Do not paste it into a chat or leave it on a shared screen. The token is new every time the program starts, unless you set one with --admin-token.

When you open the Admin address, the app takes the token out of the address bar and remembers it in that browser, so it does not stay in the address you see or share. That browser stays an admin until the token changes (the next start, unless you set one) or you sign out.

Options​

Usage: earshotd [OPTIONS]
OptionDefaultWhat it does
--port <PORT>4780The TCP port for the web app and API.
--bind <BIND>0.0.0.0The network address to listen on. 0.0.0.0 means every address this computer has. 127.0.0.1 means this computer only.
--data-dir <DATA_DIR>The operating system's data folder + EarshotWhere the show file and history live. Also read from the environment variable EARSHOT_DATA_DIR. See Data and files.
--demoOffPlay a scripted demo show. Your own data is not read or written.
--models-dir <MODELS_DIR>EARSHOT_MODELS, else <data-dir>/modelsWhere speech models live.
--web-dir <WEB_DIR>apps/web/dist, if it existsThe built web app to serve.
--admin-token <ADMIN_TOKEN>Random, printed at startupThe token that makes a client an admin.
--allow-host <NAME>NoneAn extra name people may use to reach this host (a DNS name, or a reverse proxy's name). Repeat the flag for more names.
-h, --helpPrint the options.
-V, --versionPrint the version.

Things there is no option for in this build: a certificate (Earshot serves plain http), and the OSC ports (set those in the app, under Setup, Show control).

--bind and --port​

There is no Setup screen for the network address or the web port. These two options are the only way to set them for the headless program.

  • If the port is already in use, earshotd stops with an error ("could not start the server"). Choose another with --port.
  • With --bind 127.0.0.1, only a browser on the same computer can connect, and Setup, Access has no address to offer the crew.
  • The OSC TCP port cannot be the same as the web port.

--allow-host​

Earshot refuses any request made to a name it does not recognise as its own. People who type such a name see "This address isn't one the host recognises. Use the address shown on the operator's screen."

These always work, with no option needed:

  • any IP address,
  • localhost,
  • the computer's own name (also with .local).

Any other name, such as a venue DNS name or the name of a reverse proxy in front of Earshot, is refused until you add it:

earshotd --allow-host earshot.venue.example --allow-host comms.venue.example

--admin-token​

Without it, a new random token is made at every start, so yesterday's Admin: address stops working. Set your own to keep one address working across restarts, for example on a rack machine that starts Earshot by itself:

earshotd --admin-token "a-long-random-string-you-keep-secret"

Use a long random string. It is the key to everything.

--demo​

earshotd --web-dir ./web --demo --bind 127.0.0.1

Demo mode plays a scripted transcript on made-up channels. It needs no models and no audio hardware, and your own data folder is not read or written. For the desktop app’s setup walkthrough, see Get started with Earshot.

The Feed on a demo host, playing its scripted show. It is not a real show.

Environment variables​

VariableWhat it doesRead by
EARSHOT_DATA_DIRThe data folder. The same as --data-dir.earshotd and the desktop app
EARSHOT_MODELSThe models folder, when --models-dir is not given. Otherwise models go in models inside the data folder.earshotd and the desktop app
EARSHOT_LOGHow much goes in the log, for example EARSHOT_LOG=debug. Without it the level is info.earshotd and the desktop app
EARSHOT_DEMOSet to 1 (or true) to start the desktop app in demo mode. earshotd uses --demo instead.The desktop app
EARSHOT_LOG=debug earshotd --data-dir /srv/earshot

Logs never contain what was said, or any secret. See Privacy.

Examples​

Try it, on this computer only​

earshotd --web-dir ./web --demo --bind 127.0.0.1

Open the Admin: address it prints. Nothing is reachable from the network, and nothing of yours is touched.

A rack machine for a show​

earshotd \
  --data-dir /srv/earshot \
  --admin-token "a-long-random-string-you-keep-secret" \
  --web-dir /opt/earshot/web
  • The show, the transcripts and the models are kept in /srv/earshot.
  • The admin address is the same after every restart: http://<this machine's address>:4780/?token=<your token>.
  • --web-dir points at the built web app (the contents of apps/web/dist). Without a web app to serve, there are no screens to open.

Then, from a laptop, open the admin address, download the models (Setup, Models), patch the inputs (Setup, Patch), and set who can connect (Setup, Access). See First-time setup.

Another port​

earshotd --port 8080

Crew then open http://<this machine's address>:8080/.

Models on another disk​

earshotd --models-dir /Volumes/Models/earshot

The speech model alone is about 487 MB, and each translation pair is 80 to 240 MB.

Behind a venue name​

earshotd --allow-host earshot.venue.example

Stopping it​

Press Ctrl-C in its terminal, or send it the terminate signal (kill <pid>, or however your service manager stops a program). It shuts the engine down in order, then stops. Nothing fires while Earshot is shutting down.

What happens at each start​

  • A new session starts. The earlier ones stay in the Archive.
  • The show comes back Safe, unless Setup, Show control, Start armed is on.
  • People who signed in with the password must sign in again. Personal links keep working.
  • Unless you set --admin-token, the admin token is new.

See What happens when the host restarts.

What has been tried​

earshotd has been tested on one Apple Silicon Mac and has passed a demo startup smoke test on Windows and Linux. It has not been tested as a system service or behind a reverse proxy. See Limits and known behaviour.
