What Earshot does

Earshot is a desktop and web app for live-production crews, built by RVLT. One computer, the host, listens to many intercom ("comms") channels at once, turns the speech into text on that same computer, and shows the transcript on any phone, tablet or laptop on the show network. It can also send show-control cues (OSC, MIDI, web requests) when it hears a phrase you chose.

This manual is for the people who run the show: stage managers, sound and lighting operators, and production managers.

New to Earshot? Get started with the desktop app. Install it, follow the setup assistant, check your first transcript and connect the crew.

The Feed, showing the app's built-in mock show. Every picture in this manual uses made-up lines. None is from a real show.

What it does​

  • It listens to many comms channels at once (party lines, talkbacks, radios) through the audio inputs of one computer.
  • It turns speech into text on that computer. The speech model runs locally.
  • It shows the text as a live transcript on the host and in any browser on the show network. Each person can read it in their own language.
  • It keeps every session. You can search it and export it, and replay the audio behind a line if you chose to save it.
  • It can correct names and gear the recogniser gets wrong, with a glossary.
  • It can show who is talking when several people share one channel, if it has learned their voices.
  • It can show channels from another Earshot computer on this one.
  • It can send cues when it hears a phrase you chose, with a master Armed/Safe switch, cooldowns, a test bench and an activity log.

What it never does​

  • Audio stays on the computer unless you turn on cloud speech for a channel. Cloud speech (Deepgram) is off. You choose it for one channel at a time, and Earshot asks you to confirm. Cloud translators (DeepL, Claude) send the text of lines out, and also ask first. Nothing else sends audio or text to a company. The other things that go out are model downloads (when you press Download) and the messages your automations send while the show is Armed. Privacy has the full list.
  • Nothing is sent to a console unless the show is Armed. In Safe, automations only log "would have fired".
Speech recognition makes mistakes

Treat a phrase automation as a convenience that sits beside your normal cue calling, not instead of it. How Earshot hears numbers explains what Earshot checks before it fires a number, and what it cannot check.

What state this build is in​

This is work in progress. It runs and is tested on macOS (Apple Silicon). The headless host has passed a demo startup smoke test on Windows and Linux; their installer interfaces and desktop windows have not been tested. It has not been tried against Dante, MADI or other many-input hardware, with a real microphone on real comms, or in a real venue. Limits and known behaviour says exactly what has been tried and what has not. Read it before you trust Earshot on a show.

Not in this build yet​

These are planned. They are either not built, or built but not usable from the app. Do not rely on any of them.

FeatureWhat you will see
"Play a sound" and "Show or hide the window" actionsYou can add them to an automation, but they do not run. The automation shows a problem saying so. The other actions in the same automation still run.
A signed installerUnsigned downloads are published for macOS Apple Silicon, Windows x64 and Linux x86_64. The Mac app is signed ad hoc only and is not notarised. Windows and Linux installer interfaces and desktop windows have not been tested. There is no Intel Mac installer.
Turning on https for Earshot's own addressEarshot serves plain http. There is no setting to give it a certificate.
Encrypted links between Earshot computersThe link screen offers "Encrypted (https)", but it has not been proven end to end in this build. Treat links as not encrypted.
Choosing the network interface or web portThere is no Setup screen for them. The headless program takes --bind and --port.
Importing a speech model from a folder (for a venue with no internet)There is no screen for it. Download the model once while you have internet.

How to read this manual​

Before your first show, read these four:

  1. This page.
  2. Safe and Armed, even if you only plan to read the transcript. In the default access mode anyone on the network can arm the show.
  3. Limits and known behaviour.
  4. Troubleshooting, so you know where to look when something is not doing what you expect.

How this manual is written​

  • Things you press are in bold: Hold to arm, Make safe, Download.
  • Words the app shows you are in "quotes", exactly as they appear.
  • Things you type, addresses and file names are in this type.
  • Setup, Models means: open the Setup view, then the Models section.
  • A red box means something can send a cue or lose part of the show. A yellow box means something is untested or easy to get wrong.
  • Where a feature has only been tried on computer-made voices, or never against the real service, the page says so. Those sentences are there on purpose.
